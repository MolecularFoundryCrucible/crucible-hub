# API integration

This document owns Hub-side conventions for consuming the Crucible API: the pinned contract, server functions and errors, Query keys and hydration, reads and pagination, mutations and invalidation. It does not list endpoints or fields: `contracts/crucible-api.json` and the generated `src/generated/crucible-api.ts` are the reference, and `crucible-api` owns paths, schemas, authorization, and resource semantics. Runtime boundaries are in [architecture](architecture.md), sign-in and sessions in [authentication](authentication.md), and open API requests in the [Crucible API handoff](crucible-api-handoff.md).

## Pinned contract

| File                               | Role                                                                                                                   |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `contracts/crucible-api.json`      | Reviewed OpenAPI input, never fetched at build or startup                                                              |
| `contracts/crucible-api.lock.json` | The only record of the API release, source revision, digest, and `minimumRelease`                                      |
| `src/generated/crucible-api.ts`    | Generated by `npm run api:generate`; never hand-edited                                                                 |
| `src/server/crucible/`             | Server-only transport, privilege mode, and safe errors                                                                 |
| `src/data/crucible/`               | Adapters (`*.server.ts`), server functions (`*.functions.ts`), Query options (`*.queries.ts`), and browser-safe models |

`CRUCIBLE_API_BASE_URL` includes the API's path prefix (`/api/v4` on the hosted service); contract paths are relative to it. The release image carries `minimumRelease` as the `gov.lbl.crucible.api.min-version` label.

To refresh, a maintainer runs `npm run api:fetch -- vX.Y.Z`, which downloads the release's `crucible-api.json` and `.sha256` assets with the GitHub CLI verifies the digest, writes the contract and lock, and regenerates the client. Work against an unreleased revision uses the API's deterministic export (`uv run python -m scripts.export_openapi` without `API_CONF_FILE`, or the `openapi-<commit>` artifact of a merge to `main`) with `minimumRelease` set to `null`. Then review removals, required fields, unions, nullability, pagination, security, and deprecations, update adapters and tests, and run `npm run validate`. A contract mismatch is raised with the API owner, never patched over in Hub.

## Server functions and errors

Browser code calls typed server functions and never imports API transport, sessions, credentials, or a browser-configurable API origin. Each private server function validates its input, resolves the authenticated identity on the server, propagates the abort signal, applies a bounded timeout, makes one generated operation or a small justified aggregation, and returns only a minimal browser-safe result. Capabilities guide presentation, never authorization.

The client in `src/server/crucible/client.server.ts` sends `Crucible-Privilege-Mode` on every request and rejects a response whose applied mode is missing or different. Routine requests use the global mode; Administration requests that need elevation use an explicit elevated client.

Server functions return serializable `HubResult<T>` unions. Failures reach feature code as one envelope:

```ts
type HubApiError = {
  kind:
    | "unauthenticated"
    | "forbidden"
    | "not-found"
    | "conflict"
    | "validation"
    | "rate-limited"
    | "cancelled"
    | "timeout"
    | "upstream"
    | "unexpected"
  message: string
  correlationId: string
  retryable: boolean
  fieldErrors?: Record<string, string[]>
  retryAfterSeconds?: number
}
```

`401`, `403`, `404`, `409`, `422`, and `429` map to their named kinds, other HTTP failures to `upstream`, and transport failures to `cancelled`, `timeout`, or `unexpected`. A numeric `Retry-After` becomes `retryAfterSeconds`. A `422` whose detail has type `unsupported_character` or `invalid_number` names the field. The envelope never carries headers, cookies, credentials, signed URLs, raw bodies, stack traces, or internal addresses.

Hub creates a correlation ID for every document, server-function, and server-route request and returns it as `X-Correlation-ID`; it never trusts a browser value and does not yet reach API logs (see the handoff). A failed server operation logs one structured line with the correlation ID, operation name, status, error type, and contract issue paths, and never response or request values, credentials, full URLs, or personal or scientific content. Cancellation is not logged as a failure.

## Server features

Hub reads `GET /features` with the account when it loads and hides what the server has switched off: `uploads`, `ingestion` (after upload), `printing`, `proposal_sync`, and `passwords`. A missing or unreadable list counts every feature as on (`src/data/crucible/features.ts`). Hub-side settings narrow this further:

| Setting                                | Effect                                                               |
| -------------------------------------- | -------------------------------------------------------------------- |
| `HUB_UPLOADS_ENABLED=true`             | Required with the `uploads` feature for browser uploads in API modes |
| `HUB_UPLOAD_INGESTION_ENABLED=true`    | Required with `uploads` and `ingestion` for ingestion after upload   |
| `HUB_ACCOUNT_PREFERENCES_ENABLED=true` | Enables account preferences and recently viewed history in API modes |

Fixture mode always enables uploads and ingestion after upload, and enables preferences unless the setting is `false`; the `degraded` fixture scenario switches every API feature off.

## Query keys and hydration

TanStack Query is the only browser owner of Crucible server data. Loaders call `ensureQueryData` or prefetch the exact options their components read. Every authenticated key starts with the identity scope:

```ts
type IdentityScope = readonly [
  "crucible",
  serverId: string,
  accountMfid: string,
  privilegeMode: "normal" | "elevated",
]
```

Keys append stable MFIDs, representation names, and normalized primitive parameters, never credentials, signed URLs, user objects, client instances, display labels, or raw filters. Slugs are lookup input only. A server, account, or credential change replaces the Query client before another identity renders. Turning off Administrator view cancels and removes elevated Queries once the route has reloaded in normal mode. Query persistence is off.

Collection rows, search results, detail, relationships, files, and capabilities are distinct representations: a lightweight row never seeds or overwrites detail. `null` or omitted members and links mean unavailable, an empty list means available and empty, and `null` capabilities mean no guidance rather than denial.

Server rendering dehydrates only successful, approved, identity-scoped Query families, including elevated ones (their keys carry the privilege mode) and the caller's preferences, so the first browser render matches the server. It never dehydrates errors, session data, credentials, raw search text, unknown families, or one-time keys. Public person data carries only display name and canonical identity.

Query functions pass the abort signal through the server function, which combines it with the timeout. Cancellation-sensitive views use `useQuery` with local pending state rather than Suspense, and a changed search or filter aborts superseded work.

## Reads and pagination

### Resource inspector reads

Shells, identity-only lookups, and project labels read a summary projection without scientific metadata, relationships, or members. Overview and the inspector read canonical detail with links, metadata, and owner; when Overview is the destination the shell loads detail directly, and cached detail satisfies a summary read. Graph, Manage, and Processing do not fetch those fields unless their own content needs them. The inspector renders pending identity from the row's name and type, and does not prefetch neighbours, files, downloads, counts, or members. Relationship references carry name, MFID, type, direction (`source` is parent, `target` child, `undirected` associated), and nullable `relationship_type`, so rows need no per-item detail reads. Navigation behavior is in decisions [0008](../decisions/0008-inspect-linked-resources-in-place.md), [0010](../decisions/0010-inspect-project-data-in-place.md), and [0012](../decisions/0012-inspect-global-data-in-place.md).

### Collections and cursors

Samples, datasets, projects, and instruments use cursor chains: omit `cursor` first, follow `next_cursor`, and never mix in `offset`. Directory reads request up to 100 rows and totals, and accept a smaller page. The route search owns shareable filters; an identity-scoped Infinite Query owns the pages. The continuation row loads the next page as it nears the viewport and keeps a Load more button for keyboard use; it stops after an error until retried, and never discards loaded pages or rewrites the URL. Changing a committed filter starts a new chain. Hub never sorts, groups, facets, or filters a partial page and presents it as the whole collection.

Sample and dataset reads send `affiliation=member` by default, `affiliation=owner` for the ownership filter, and none when public data is included or Administrator view is on; owner filters use `owner_ref` and `owner_is_null`. On an instrument page, its members read with `affiliation=member&affiliation=instrument` so they see every dataset on the instrument, unless they choose Personal (`access=personal`). Project lists accept only `affiliation=owner`. Affiliation is part of every key so rows and counts never cross modes.

Detail pages keep the loaded sequence for Previous and Next without copying it into route state. Next at the end of the loaded pages calls the same Infinite Query continuation. A page opened outside a list rebuilds a sequence with two `anchor_mfid` reads using the same filters and sort in opposite directions; Hub reverses the preceding side, drops the duplicate anchor, and continues each side by its own cursor without resending the anchor. A missing or excluded anchor is a local error.

Project Data sends the canonical `project_mfid` with an explicit `project_scope` (`all`, `assigned`, or `shared`), because the API's default is not Hub's. Created filters send inclusive UTC bounds (`T00:00:00+00:00` to `T23:59:59.999999+00:00`) and never use the scientific `timestamp`. Invalid URL state shows a local correction and never causes an unfiltered request.

Search is explicit-submit. Project search passes `project_mfid` with `project_scope=all`. Metadata search (`GET /resources/metadata/search`) groups project, instrument, sample, and dataset results and keeps raw text out of dehydrated state and telemetry. Picker autocompletes debounce and let superseded requests cancel.

### Facets

Each facet field, bucket order, and filter context is its own Infinite Query chain; the key includes resource kind, field, facet `sort` and `direction`, and every normalized filter, while the opaque cursor stays a page parameter. A bucket set is complete only when `next_cursor` is `null`. A filter control excludes its own field from its bucket request. Buckets show the API's `label` and filter by the raw `value`: a concrete value maps to the matching exact collection filter and a `null` bucket to its `*_is_null=true` selector. The URL distinguishes no selection, an empty string, and `null`. Hub never parses facet cursors or loads every bucket's resources.

### Resource graph

The Graph tab loads three independently keyed reads of `GET /resources/{resource_mfid}/graph`: depth-three upstream lineage, depth-three downstream lineage (kept separate so traversal never turns back into sibling branches), and depth-one associations. Expanding a node starts another depth-one read rooted there. The view merges responses by node MFID and edge ID without copying them out of Query. `expansion_availability` decides which expand controls appear, and `false` wins when a node appears in several responses. Truncation stays visible, and graph reads never seed resource detail. Presentation is in [decision 0026](../decisions/0026-explore-bounded-resource-graphs.md).

### Files, downloads, and processing

A download link is a transient result of a user action, not Query data. The server requests `GET /files/{file_id}/download_link` only after activation, returns the URL with `Cache-Control: no-store`, and the browser navigates to it at once with no referrer. The URL never enters HTML, route state, caches, logs, telemetry, or test artifacts. Opening a file name goes through Hub's `/files/$fileMfid/open` route with `disposition=inline` ([decision 0034](../decisions/0034-open-stored-files-inline.md)). A `409` with `storage_location_invalid` or no code means the file is unavailable, not a retryable error.

Dataset Processing keeps files (`GET /datasets/{dataset_mfid}/files`), ingestion history (`GET /ingestion_requests` by `dataset_mfid`), and post-processing runs in separate Queries. Each file shows the newest returned ingestion request, and an unmatched file beyond the returned page has no status rather than an invented one. Post-processing lists pipelines from `GET /pipelines` and runs from `GET /postprocessing_runs` by `dataset_mfid`, refetching every 10 seconds while a run is `requested` or `running`.

### Home and directories

Home reads equally bounded sample and dataset pages ordered by creation time and merges them for Recently added (All or Mine), plus up to seven of the caller's projects and active instruments with the caller's role from each item. Another person's projects use `GET /users/{user_ref}/projects`, where `role` is theirs. Project and instrument directories sort on the server, keep `include_owner=true` where they show an Owner column, and include result-shaping options in their keys. Activity times (`last_activity_at`, `last_active_at`, `last_used_at`) render through `ActivityTime` at hour granularity, matching how the API records them.

## Mutations and invalidation

- Use the authoritative mutation response for the same shape, merge only confirmed fields into detail, and invalidate the smallest dependent set of collections, facets, sibling sequences, search, graphs, and summaries.
- No optimistic updates for authority, ownership, access, provenance, deletion, uploads, ingestion, relationships, or scientific metadata. The exceptions are account preferences and recently viewed history, which roll back on failure.
- Multi-item actions (membership adds, access grants and revocations, deletion reviews) run as sequential single operations, keep confirmed successes, and keep failures selected for retry.
- Multi-stage workflows keep completed non-secret stages and retry only what is incomplete; a confirmed resource is never recreated.
- Every mutation server function authenticates, validates, and checks same-origin independently.
- A `403` asking for a recent sign-in opens the shared re-authentication prompt and resumes the action.

### Account

| Area                 | Convention                                                                                                                                                                                                                                                                                                                                                                         |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Profile              | Send only changed fields to `PATCH /account/profile`, then reread so capabilities stay authoritative. Email stays in the account-owned representation only. A debounced exact `GET /users?username=` lookup flags taken names but cannot prove availability.                                                                                                                       |
| Preferences          | Read `GET /account/preferences`, then send an RFC 7396 merge patch of changed keys with `If-Match`. On `412 etag_mismatch` the server rereads and reapplies the patch once. Writes are serialized and optimistic. Unknown keys are dropped on read and never rewritten. URL parameters always win over preference defaults (`data_group_by`, `default_sort`, `resource_sequence`). |
| Recently viewed      | Page views `POST` to `/account/recent-resources` at most once a minute per resource, unless `record_recent_resources` is `false`; previews and prefetch never record.                                                                                                                                                                                                              |
| Sessions and sign-in | `/account/sessions`, `/account/identities`, `/account/auth-events`, and `/account/password` back the Security tab. Signing out this browser uses Hub's own sign-out.                                                                                                                                                                                                               |
| API keys             | List `GET /account/apikeys` by `state` with cursors. Create with a name and optional expiry; the key is shown once in mutation-local memory and never enters Query. Rename and revoke per key. Creation needs a Hub session, so API-key development mode hides it. Hub does not call `/account/apikey/regenerate` or `/account/verify`.                                            |

### Administration

Administration reads and writes use elevated, identity-scoped, no-store server functions and require Administrator view. People use `GET /users` and `/users/{user_ref}` routes for profile edits, `PATCH /users/{user_ref}/platform_role`, disable and enable, approval and rejection, sessions, sign-in methods, password links, and per-key revocation (`DELETE /users/{user_ref}/apikeys/{key_id}`). Service accounts are created with `POST /service_accounts`, change role through `PATCH /service_accounts/{service_account_ref}`, and rotate with `POST /service_accounts/{service_account_ref}/rotate_key`; one-time keys stay in mutation-local memory. Role changes may take up to the API's authentication-cache lifetime (60 seconds by default) to apply, and the UI does not imply otherwise.

Deletion requests use `GET /deletion_requests` (`scope=submitted` or `reviewable`) and `GET /deletion_audit` for approved history, both with API ordering and cursors. Eligible administrators use elevated authority inside the deletion destination without changing the global mode. Per-request `capabilities.can_review` is the only signal for review actions.

### Resources

| Area                       | Convention                                                                                                                                                                                                                                                                                                                                    |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Creation                   | Omit `unique_id` and owner and let the API assign the MFID ([decision 0025](../decisions/0025-let-api-assign-creation-mfids.md)). Send `project_mfid` and `instrument_mfid` only when chosen. A project's `owner_ref` can differ from the caller only in Administrator view. Sample links on a new dataset run only after confirmed creation. |
| Summary and Overview edits | Send only changed descriptive fields. Unrecognized timestamp strings stay untouched.                                                                                                                                                                                                                                                          |
| Metadata                   | A bounded JSON object (1 MiB, no non-finite numbers, NUL, lone surrogates, or noncharacters). Additions and replacements use the merge operation; any top-level removal needs explicit full-replacement confirmation.                                                                                                                         |
| Relationships              | Gated by the source's `can_edit`. Parent-child links may send `is_derived_from` or `is_part_of` describing the child; associations are untyped. After link or unlink, reread both resources with links and invalidate both graphs. Self-links are rejected locally.                                                                           |
| Access and Manage          | ACLs load only on Manage entry. `can_manage_access`, `can_transfer`, and `can_request_deletion` gate their sections; `max_grant_role` caps new grants. Per-entry `capabilities` (`can_remove`, `can_change_role`, `assignable_roles`) alone decide row controls. Owner, primary-project, instrument, and unknown grants are read-only.        |
| Ownership and assignment   | Ownership transfer (`new_owner_ref`) and project moves call the API once to preview and again with confirmation. Dataset instrument assignment has no preview and is confirmed locally.                                                                                                                                                       |
| Deletion                   | Only the reviewed deletion-request operation, never direct deletion. Submission and review invalidate collections, facets, search, graphs, summaries, and detail.                                                                                                                                                                             |
| Files                      | Rename and delete through `/files/{file_id}`, gated by `can_edit` and `can_delete_files`.                                                                                                                                                                                                                                                     |
| Thumbnails                 | A separate no-store Query read after hydration; writes reread the full list. Payloads never enter detail, URLs, logs, or persistence.                                                                                                                                                                                                         |
| Ingestion                  | `POST /files/{file_id}/ingest` per file, never retried automatically because each call creates a request; non-atomic across files.                                                                                                                                                                                                            |
| Post-processing            | `POST /datasets/{dataset_mfid}/postprocess` with an `Idempotency-Key`, then invalidate the run list.                                                                                                                                                                                                                                          |

Uploads follow [decision 0005](../decisions/0005-direct-object-storage-uploads.md): Hub server functions own initiation (with `Idempotency-Key`), part signing, status, completion, and abort under strict validation and `no-store`, while the browser hashes and sends parts straight to object storage. Signed part URLs live only in the upload runner's memory. Replacing an existing stored file initiates at `/files/{file_mfid}/upload/multipart/initiate` with `If-Match` set to the file `etag` the person saw; `412 etag_mismatch` or a changed file rereads the list and asks again. Completion invalidates exactly the dataset's files Query. Part size, concurrency, and retry limits live in `src/data/crucible/uploads.ts` and `src/features/dataset-files/`.

| Area                 | Convention                                                                                                                                                                                                                                                                                |

## Validation

`npm run validate` runs formatting, lint, types, unused-code, tests, contract drift (`api:check`), the server boundary, design tokens, documentation links, and secrets checks, then the production build. Adapter and contract tests cover input validation, error mapping, cancellation and timeout, cursor behavior, detail-preserving caches, approved hydration, and client replacement between accounts. Browser tests run on fixtures; live services are never a routine test dependency. The API-key development mode is refused in production and described in [authentication](authentication.md#api-key-mode).
