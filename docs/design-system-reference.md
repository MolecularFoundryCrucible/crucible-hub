# Crucible Hub Design System Reference

Status: Active design-system contract (detailed reference)

Date: 2026-10-20

Start with the quick reference in [`design-system.md`](design-system.md). This document holds the detailed rules behind it.

## Scope and principles

This document owns Hub tokens, themes, component policy, responsive behavior, accessibility, and visual validation. [`product-brief.md`](product-brief.md) owns product intent, [`information-architecture.md`](information-architecture.md) owns routes and navigation structure, [`architecture.md`](architecture.md) owns runtime boundaries, and [decision 0003](../decisions/0003-owned-design-system.md) owns the decision to use an owned system.

Hub is a desktop-first scientific workspace that shares Lens's semantic hierarchy and state discipline, not its phone dimensions, Compose structure, navigation, or Material defaults. Use semantic meaning before appearance, calm dense rows and tables, explicit accessible states, native HTML before managed primitives, usable full MFIDs, and one behavior contract across light and dark themes. Accessibility is a release property.

## Ownership and tokens

| Layer                                | Owner                        | Primitive values           |
| ------------------------------------ | ---------------------------- | -------------------------- |
| Primitive scales and semantic themes | `src/styles.css`             | Allowed only here          |
| Controlled shadcn primitives         | `src/components/ui`          | Shared tokens only         |
| Crucible domain components           | `src/components/crucible`    | Semantic tokens only       |
| Feature screens and routes           | `src/features`, `src/routes` | No primitive visual values |

Generated primitives enter `components/ui`, are reviewed, and become Hub-owned source. Feature code must not introduce colors, arbitrary utility values, shadows, type sizes, spacing, radii, breakpoints, z-index values, or motion durations. A missing role is a design-system change, not a local exception.

Primitive scales use a 4 px base and named spacing roles, repository-pinned self-hosted Noto Sans and Noto Sans Mono (the `--font-mono` token behind every `font-mono` use, code blocks, and the metadata editor, with system monospace as fallback), shared radius and elevation roles, named layers, and named responsive breakpoints. Semantic utilities own each typography role completely: feature code does not recreate roles with primitive Tailwind size, weight, line-height, or tracking utilities. Shared class composition recognizes every semantic typography role as a font-size utility so foreground utilities cannot replace it. Use tabular numerals for changing data, selectable monospace MFIDs, and no interface text below 12 px.

| Role                                      | Size / line height / weight | Use                      |
| ----------------------------------------- | --------------------------- | ------------------------ |
| `title-page`                              | 28 / 36 px / 600            | Route title              |
| `title-entity`                            | 24 / 32 px / 600            | Entity title             |
| `title-section`                           | 18 / 28 px / 600            | Section, dialog, group   |
| `body-prominent`                          | 16 / 24 px / 400            | Spacious body and inputs |
| `body`, `identifier`, `label`             | 14 / 20 px / 400 or 600     | Rows, MFIDs, controls    |
| `supporting`, `label-compact`, `overline` | 12 / 16 px                  | Secondary content        |
| `metric`                                  | 24 / 32 px / 600            | Bounded summary          |

Top-level read-only field labels in Summary, Identity, Context, profile, and management cards use the 14 px semibold `label` role with muted foreground, and their values use the 14 px regular `body` or `identifier` role with normal foreground. Reserve the 12 px `supporting` role for hints, secondary identifiers, dense scientific metadata keys, and supplementary status text. Instructional copy, confirmations, and tooltips emphasize a referenced resource's displayed name with semantic strong text so it remains distinguishable from the surrounding wording, while accessible names remain plain-language actions. Group headings that sit above a run of labelled controls, such as sidebar groups and Filters panel sections, use the 12 px `label-compact` role with muted foreground, so they stay quieter than the 14 px field labels beneath them.

Use 44 px minimum primary touch controls. Dense pointer-oriented rows may be 36 px only when each target is at least 24 by 24 px, separated, and keyboard reachable. Semantic layout roles include app header height, page gutter, content and reading widths, section gaps, dense pill roles, and a 320 px initially resizable metadata editor. Use restrained 4, 8, 12, and 16 px radius roles only after fixture calibration. Resting elevation is `level-0` flat, `level-1` sticky or raised, `level-2` menu or popover, and `level-3` modal. Cards use the card surface with a restrained boundary; popovers and dialogs use the raised popover surface with stronger elevation. Prefer surfaces and borders to decorative shadow. Responsive behavior is defined once in `src/styles.css` (see Responsive layout below); components prefer container queries. Named layers, from lowest to highest, are `--layer-raised`, `--layer-graph-overlay`, and `--layer-graph-action` (stacking inside a component), `--layer-sticky`, `--layer-floating-utility`, `--layer-navigation` (sidebar and app header), `--layer-route-progress`, `--layer-modal` (dialogs, alert dialogs, sheets, and their backdrops), `--layer-popover` (menus, popovers, comboboxes, hover cards), `--layer-tooltip`, and `--layer-toast`, applied as `z-(--layer-*)`. Popovers sit above modals because pickers and menus open inside dialogs and the inspector; a modal blocks everything outside it, so no popover from behind it can be open at the same time.

Motion follows [decision 0036](../decisions/0036-centralize-motion.md): it explains change and never decorates. Durations are `--motion-fast`, `--motion-standard`, and `--motion-deliberate` (120, 180, and 240 ms, as `duration-fast`, `duration-standard`, `duration-deliberate`) with the `ease-standard`, `ease-enter`, and `ease-exit` easing roles. Entering decelerates with `ease-enter`; leaving accelerates with `ease-exit` and is one step shorter. Bare `transition-*` utilities default to the fast duration and standard easing. Every animated element uses exactly one role:

| Role               | Used for                                            | Enter                                                                     | Exit                                       |
| ------------------ | --------------------------------------------------- | ------------------------------------------------------------------------- | ------------------------------------------ |
| `press`            | hover, press, focus, and selection color changes    | fast, standard easing                                                     | same                                       |
| `anchored-overlay` | menus, popovers, comboboxes, hover cards, tooltips  | fast, `ease-enter`, fade plus 95% scale                                   | fast, `ease-exit`, fade                    |
| `modal`            | dialogs, alert dialogs, and their backdrops         | standard, `ease-enter`, fade plus 95% scale                               | fast, `ease-exit`, fade                    |
| `sheet`            | side sheets and the resource inspector              | deliberate, `ease-enter`, slide from its edge plus fade                   | standard, `ease-exit`                      |
| `toast`            | notifications                                       | standard, `ease-enter`                                                    | fast, `ease-exit`                          |
| `reveal`           | conditional sections that open and close in place   | standard, height plus fade                                                | standard                                   |
| `content-enter`    | newly arrived rows, appended pages, swapped panels  | standard, `ease-enter`, fade                                              | none                                       |
| `section-change`   | route-backed section tabs                           | standard crossfade through a view transition                              | same                                       |
| `layout`           | sidebar collapse, inspector docking, graph relayout | standard; graph relayout and viewport moves deliberate                    | same                                       |
| `pending`          | dimming a region whose data is reloading            | after the indicator delay, fast fade                                      | fast                                       |
| `progress`         | the route progress bar and inline spinners          | bar after the progress delay (500 ms), spinners after the indicator delay | finishes forward to full width, then fades |

Each role has one home. The overlay primitives in `src/components/ui` apply `anchoredOverlayMotionClassName`, `modalMotionClassName`, and `backdropMotionClassName` from `src/lib/motion.ts` and the `.motion-sheet` and `.motion-toast` classes; each is a CSS transition on Base UI `data-starting-style` and `data-ending-style` in `src/styles.css`, so an interrupted open or close reverses smoothly and feature code never sets overlay timing or layers. `Reveal` (Base UI Collapsible with the `.reveal-panel` height and opacity transition, keeping its last content while it closes) shows or hides conditional content such as the Administration links. `enterMotionClassName` fades content in, and `useEnteringKeys` limits it to items that arrive after the first render, as in the sidebar Recent list and rows appended to collection tables. `PendingRegion` marks a region that is reloading with `aria-busy` and `data-pending` and dims it to `--motion-pending-opacity` only after `--motion-indicator-delay` (200 ms), so fast responses never flash; Data, project data, search, the directories, the inspector, and the page during an Administrator view switch use it, and its stale content stays readable. `useDelayedFlag` applies the same delay to other indicators, such as `DelayedPendingIcon` on Load more buttons; `RouteProgress` waits for the longer `--motion-progress-delay` (500 ms). Dialog content keeps its last state until the close animation ends through Base UI `onOpenChangeComplete` or `useExitSafeMount`. Script-timed motion (list growth, the graph) reads tokens through `motionDuration`, which accepts minified values and returns 0 under reduced motion. Controls in flight show pending with `aria-busy` rather than `disabled`, so they stay at full strength; copy controls report success for 2 seconds through `useCopyFeedback`. Metadata disclosures animate their height through `::details-content`, and resource, project, and instrument section tabs crossfade only the section panel through a router view transition while the header, tabs, and navigation stay still. Search-only navigation, such as filters and the inspector, never starts a view transition. Browsers without support change instantly. No continuous decoration. One reduced-motion block in `src/styles.css` removes movement: overlay scale and slide offsets, `Reveal` height motion, graph motion, view-transition animation, and smooth scrolling; the pending dim keeps its delay but drops the fade. The design-token check rejects raw durations, cubic-bezier curves, arbitrary `duration-[...]`, `delay-[...]`, `ease-[...]`, and `animate-[...]` utilities, numeric `duration-*` and `delay-*` utilities, Tailwind `ease-in`, `ease-out`, `ease-in-out`, and `ease-linear` utilities, keyframe animation classes (`animate-in`, `fade-in`, `zoom-in`, `slide-in-from-*` and their exit forms) outside `src/lib/motion.ts`, raw times in inline transition styles, and numeric or arbitrary `z-*` and `z-index` layers everywhere under `src`, including `components/ui`. Property-only `transition-[...]` lists stay allowed.

Color has two layers in `src/styles.css`. The palette (`--palette-neutral-1` to `13`, `--palette-blue-1` to `10`, `--palette-orange-1` to `7`) holds raw OKLCH values with the three Crucible brand colors as anchors; nothing outside `src/styles.css` references it. Roles reference the palette and are the only colors components use; light and dark themes swap only the roles, and Tailwind's default color palette is disabled so only role utilities exist. Roles cover background, card, popover, primary and primary hover, secondary (selected surface), muted, accent, action surface, action border (soft, text buttons), border strong (3:1: inputs, icon-only controls), action hover, action pressed, overlay, destructive, success, warning, info, border, input, ring, selection, sidebar, and data visualization. Every role with a literal light value must also define a dark value, which the contrast check enforces. The light canvas uses a restrained cool neutral behind white cards and popovers, while muted, secondary, accent, and action surfaces remain distinct enough to communicate hierarchy without decorative color. Resource pairs cover sample, dataset, project, instrument, person, file, and service account. Combined Data navigation uses the Crucible dark-blue and light-blue brand pair, while individual datasets use mineral jade-emerald, samples use plum-magenta, projects use cobalt blue, instruments use brass-gold (distinct from the Crucible orange selection role), people use cerulean cyan, service accounts use indigo-violet, and files use subdued steel-slate. Renderers derive categorical identity from the same resource roles used by normal application surfaces. State, type, permission, and lifecycle always also use text, icon, shape, position, or pattern. Do not derive hierarchy with arbitrary foreground opacity.

Light, dark, and system preferences share these roles. Resolve theme before first paint, set `color-scheme`, react to system changes only in system mode, and persist only the preference, never derived colors. Any browser preference must be account-neutral and safely cleared or recomputed on identity change. Validate every semantic pair in both modes.

Badges use semantic variants rather than feature-level color classes. Semantic status badges use a quiet tinted surface, semantic foreground, and restrained boundary so routine states do not compete with actions: success green for Valid, Complete, and Active; information blue for pending, queued, running, and processing; warning orange for maintenance, retrying, limited results, and states requiring attention; and destructive red for failed, invalid, and decommissioned states. Status labels and tones come from one catalogue in `src/lib/status.ts`, keyed by kind of record (resource, ingestion, deletion request, service, database) because the same word can carry a different tone in each, and `StatusBadge` renders them in sentence case. Neutral metadata, roles, counts, visibility, and editing context use default, secondary, outline, or their dedicated domain variants because they do not express severity. Public and Private use `VisibilityBadge`, which pairs the semantic `public` (info-tinted) or `private` (neutral) badge variant with an inline globe or lock access icon. Role badges never use hue, so status stays the only color in a row; they show the permission ladder with three neutral `Badge` variants, mapped once in `AccessRoleBadge`: `emphasis` (accent fill, strong border) for roles that manage access (Owner and Admin), `outline` for roles that change data (Editor, Contributor, platform Support), and `muted` for read-only or no access (Viewer, platform None, unknown roles). Owner adds the `OwnerRoleIcon` crown so it stands out from Admin without a color; it is presented as Lead in project membership and Manager on instrument operators while the underlying authorization role remains `owner`. This follows the common practice of neutral role labels (GitHub, GitLab, Google Drive) and the GitLab Pajamas and Atlassian rule that status colors carry status meaning only.

## Identity and credentials

Person identity uses the shared `PersonIdentity` primitive (`inline` for full or first-initial name in dense fields, `collection` for single-line truncated table rows, `stacked` for name over normalized `@username` with an accessible principal-type icon, and `avatar` to add a small, default, or large initial avatar). Human identities use the person icon and person-colored avatar border, while service accounts use the robot icon and semantic service-account violet for both the icon and avatar border around the same neutral fill. The API account-type field is authoritative, and visible icon shape plus its accessible name keeps the distinction independent of color. Shared identity, tooltip, and search presentations use the `@username` handle form for both people and service accounts, while page titles, explicitly labelled username or account fields, credential workflows, copied values, and accessible names use the raw username without `@`. Missing names fall back through supplied display name, raw username, and MFID; missing usernames use consistent unavailable copy.

Text cut off by `truncate` or `line-clamp` uses `TruncatedText`, which shows the full text in the Hub tooltip on hover or keyboard focus only while it is cut off. Icon-only marks and sidebar actions name themselves in the Hub tooltip too (`SidebarMenuAction` and `SidebarMenuSubAction` take a `tooltip` prop). Browser-native `title` tooltips are not used, except on `<time>` elements for the exact date.

Resource identity uses `ResourceIdentity` for the semantic type icon, display name, optional context, and optional MFID in stacked and collection presentations. Samples and datasets fall back to `Untitled sample` or `Untitled dataset` when a name is missing or blank; projects and instruments fall back to their project or instrument ID and then their canonical MFID. Resource names expose preferred break opportunities after scientific separators while preserving their visible and copied value. Sample and dataset search identities show the project icon and project ID followed by a middle-dot separator and sample type or measurement on the same supporting line when the search response provides them.

`PersonLink` provides canonical person navigation with the shared `IdentityHoverCard` preview wherever a person identity is linked. `ResourceIdentityLink` uses `IdentityHoverCard` only for project and instrument references inside sample and dataset lists or detail pages, where previewing context avoids interrupting the data workflow; project and instrument identities on their own directories, Home, search, access, and other primary navigation surfaces remain direct links without hover previews. Hover previews repeat the entity identity (with avatar on the left for people), place the fixed-length MFID on its own non-wrapping full-width line, and show only context already available to the current surface. They open on pointer hover or keyboard focus, suppress browser-native title tooltips, never contain information required to navigate or understand the row, and follow the canonical link directly on activation. Chooser buttons use display-only identity primitives so selection does not navigate.

Keyboard keys, such as the search shortcut hint and the Shortcuts dialog, use the shadcn `Kbd` primitive. `MfidText` owns identifier typography wherever copying is not offered, while `MfidValue` adds the standard copy action. Both use the 14 px `identifier` role for primary fields and a muted 12 px `supporting` presentation for secondary identity in rows, tooltips, choosers, search results, and the inspector. Resource identity includes a complete selectable MFID that uses the full card width, stays on one line when the compact viewport permits, and permits omission of its decorative field icon at the narrowest supported width so the identifier and copy action remain together. The QR scanner shows the camera in a square viewfinder (at most 60% of the viewport height) with the scanned region, the centered two thirds, framed by rounded corner marks in the `scan-frame` role (Crucible orange) and the area outside it dimmed by `scan-mask`; the frame is static, an unrecognized code leaves scanning running with an inline status, and the manual fallback uses `IdentifierInput`. `MfidQrCode` renders the raw MFID at 112 px with ghost `icon-sm` Copy and Print actions beneath it and a specification-compliant quiet zone. The Identity card sizes it from its own width (an `identity` container query): the code sits top-right beside the fields whenever the full MFID fits on one line next to it, shrinks to 68 px (`--spacing-qr-compact`) when that keeps the MFID on one line, and moves below the fields only on cards narrower than 20 rem. It opens a larger dialog view when activated.

Recognized timezone-aware ISO and PostgreSQL-style API timestamps display in browser-local time as abbreviated month, day, year, and 24-hour hour and minute (`Sep 6, 2026, 14:32`), formatted on the server in the viewer's time zone from the `crucible_hub_time_zone` cookie; without that cookie they use a deterministic UTC representation through the first client render and switch to browser-local formatting after hydration. Normalization accepts the API's space separator, microsecond precision, and compact UTC offsets without interpreting timezone-free values; native local date-time controls own editing and unrecognized values stay unchanged.

Human account and service-account views share the API credential card for non-secret validity, creation, expiry, loading, empty, and error states, placing Status, Created, and Expires on one row at wide widths and keeping creation and expiration together on compact and medium screens. Account capabilities use success-colored circle-check and destructive-colored circle-cross icons with accessible state names so availability remains understandable without color or status prose. Service-account administration reuses the shared person identity, service-account icon, role badge, table, card, form, dialog, and confirmation primitives, and its Identity card labels Username, Platform role, and Crucible ID while omitting the human-only email field. One-time credentials use a read-only monospaced `IdentifierInput` (the same field used to enter MFIDs and ORCIDs, which keeps the 16 px compact input size and turns off autocorrection) with an adjacent tooltip-wrapped copy action and explicit copy that the value cannot be shown again. Secret values never appear in collection rows, identifiers, notifications, links, or persistent UI state.

## Icons and actions

Routes, features, and Crucible domain components import Lucide icons only through the shared semantic catalog (`src/components/crucible/icons.ts`) or semantic icon wrappers; controlled UI primitives may own their internal implementation icons. The shared resource, principal, and data-collection type icon components own icon selection, default non-shrinking `size-icon-label` sizing, and semantic color while call sites supply only layout or explicit size classes. Icon size follows the text it sits beside, from two tokens defined once in `src/styles.css` next to the text roles: `--spacing-icon-label` (16 px, `size-icon-label`) beside 14 px label, body, and identifier text, and `--spacing-icon-supporting` (14 px, `size-icon-supporting`) beside 12 px supporting text such as the project, instrument, and MFID lines of `ResourceIdentity` and supporting `MfidValue`. Both are registered with `cn` so a supporting size replaces the default. Button icons keep the sizing owned by `buttonVariants`. Summary values and collection group facets share `SummaryFieldIcon` (colored semantic icons for linked projects and instruments, neutral icons for descriptive fields), and Identity values share a field-icon mapping for MFID, owner (selecting person or service-account icon from resolved owner type), and timestamps. Summary, Context, and Identity rows that pair an icon with a value render through `SummaryFieldItem`, which owns the label, icon gap, and wrapping. Decorative icons are hidden from assistive technology (`aria-hidden="true"`), and icons inside buttons or button-styled links declare `data-icon="inline-start"` or `data-icon="inline-end"`. Icon-only controls require persistent resource-specific accessible names and visible tooltips, and are reserved for obvious low-risk actions; text remains for unfamiliar, destructive, ambiguous, or qualified actions. No emoji, logo, or brand mark is a normal UI icon.

Recurring domain action patterns own their canonical icons, button variants, sizes, and accessible labels so features and routes do not recombine them ad hoc:

- `EditableCardTrigger` and `EditableCardActions` own read-first card Edit triggers (`EditResourceIcon`), outline Cancel, primary Save, form association, disabled state, and pending feedback.
- `CreationFormActions` owns outline Cancel and content-width submit actions (`Create` or `Register` with `PendingIcon` and multi-stage retry labels).
- `ManagementToggle` owns the pressed-state ghost `Edit` / `Done` toggle and tooltip for inline list management modes.
- `ResourceFullPageLink`, `CardViewAllLink`, `ResourceCreationLink`, and `ResourceGraphLink` own canonical navigation and creation links across cards, tables, and the inspector.
- `RotateCredentialAction`, `AccessGrantListActions`, and `UnlinkRelationshipAction` own destructive/management triggers for credential rotation, access/membership/operator list footers, and relationship unlinking.
- `RefreshButton` owns the ghost refresh control, `aria-busy` state, spinning icon, and last-updated tooltip across entity headers, the global Data toolbar, and the system status popover.

The shared `Button` primitive and `buttonVariants` helper are the only sources for general action typography, surfaces, borders, radii, internal spacing, heights, and icon sizing:

- `default` (primary: solid `--primary`, `--primary-hover` on hover): the one main action of a view and the commit at the end of a flow (Save, Create, Submit, dialog confirm). Page-header Create links are primary.
- `outline` (secondary: `--action-surface` with the soft `--action-border`, `--action-hover` on hover, `--action-pressed` via `aria-pressed`): deliberate actions that change data or open a flow that will (Add files, Choose project, Make private), form Cancel, retry, and creation links inside toolbars, cards, and the top bar. Icon-only sizes (`icon`, `icon-xs`, `icon-sm`, `icon-circle`, `table-action`) automatically use the 3:1 `--border-strong`.
- `ghost` (tertiary: no resting container): frequent, reversible, mode-entering, or navigational actions (card Edit, Edit/Done, Refresh, Browse nearby, copy, print, row open and download actions, view-all and Graph links, inspector Back, and the header toggles for the navigation sidebar and the preview pane, which share the `icon` size, a tooltip, and mirrored panel icons). Selected list items set `aria-current="page"` and receive the `--secondary` selected surface. When the content is narrower than the `labels` threshold, page actions shorten to icons while keeping their accessible names, and `CompactLabelTooltip` names them in a tooltip only while their label is hidden: Refresh, Filters, and Browse nearby show only their icons (Filters keeps its active-count badge), and Create sample, Create dataset, and the Create project, Register instrument, Create user, and Create service account page header links show the plus with the resource or account type icon.
- `warning` (warning foreground and quiet warning surface): active states requiring continued attention, such as the persistent Administrator view control.
- `destructive` (tinted destructive surface, destructive foreground, subtle destructive border) and `destructive-solid` (filled destructive surface for final confirmation footers): inline destructive entry points and irreversible confirmations, including credential rotation, revocation, leaving a project, and deletion.

Choose the tier by stakes and frequency, not by whether the action eventually changes data; when in doubt, choose the quieter tier. Hover, pressed, and selected colors come from roles, never from inline `color-mix` in component classes. Hover states may change the action surface but must retain its paired foreground. Confirmation footers do not repeat trigger icons; they show only action text and `PendingIcon` while pending. A Base UI `Button` that renders a navigation link sets `nativeButton={false}`. Feature-level `className` values may control external layout (width, flex, alignment, position) but must not override visual or sizing rules. Responsive collection links use the `table-action` size, floating Back to top controls use `floating`, MFID QR triggers use `qr`, and sidebar utilities use `SidebarMenuButton`. The design-token check enforces these boundaries and rejects raw buttons and visual `Button` overrides outside `src/components/ui`.

Small mutually exclusive view and scope choices, such as Samples and Datasets on Data and in a project's Data section, use `SegmentedControl`; long option sets, such as the search types, switch to a `NativeSelect` below the `labels` threshold instead of scrolling (built on Toggle Group) with compact text labels on a muted group surface and the standard action surface and border for the selected option. The shared `Switch` primitive owns toggle dimensions, focus treatment, and semantic color variants (including `warning` for Administrator view). Every enabled control that activates on click (buttons, links, menu items, combobox and search options, selects, tabs, checkboxes, switches, and disclosure summaries) uses the pointer cursor across its whole area while retaining native keyboard and focus behavior; text fields use the text cursor, disabled controls `not-allowed`, the sidebar rail its resize cursor, and the graph canvas `grab`. `tests/production/cursor.spec.ts` checks this on the main pages and open menus.

## Primitives and composition

[Decision 0006](../decisions/0006-use-base-ui-primitives.md) selects Base UI. Pin it in `components.json`, use the official shadcn CLI and registry, preview changes, and never overwrite Hub modifications without review. Install primitives only when needed and treat `src/components/ui` as the current inventory. Community registry components require provenance, dependency, license, source, accessibility, and theme review. Domain components accept semantic data and actions, never authorize or infer permissions, and presentational components do not fetch.

The application shell uses the square Crucible Hub logo as sidebar artwork and browser favicon, while the standalone Crucible Hub icon remains available for reviewed brand uses without a background. Crucible dark blue, light blue, and orange have dedicated brand roles: a softened light-blue surface identifies the light sidebar, dark blue identifies the dark sidebar, and the contrast-adjusted selection role based on Crucible orange marks the current destination boundary (`aria-current`) without replacing resource-type or state colors. Standalone sign-in and sign-in error pages share a centered card shell without the sidebar, with no accent stripe or glow (orange appears only in the Hub mark), the Hub mark beside the sign-in title, a content-width outlined ORCID action, a faint background Explorer logo on sign-in, and a warning icon with one retry action on the error card.

The expanded desktop sidebar uses a 16 rem reading width, places the 1 rem brand label at top, uses the 0.875 rem body and label roles for destinations, scrolls its destination groups independently when height is constrained, and keeps Shortcuts, Theme (opening a System/Light/Dark radio menu), and Collapse navigation as standard labeled menu rows in its footer. The collapsed sidebar centers the logo on the same column axis as its navigation and footer icons, represents Recent with one history action and anchored menu, condenses the Administrator view switch to a pressed shield icon (`shield-minus` when off, `shield-plus` with warning surface when on), and presents footer utilities as vertically stacked icons with named tooltips. Only the compact drawer trigger remains in the application bar on narrow screens.

Page headers use one route title, an optional semantic identity icon in a resource-tinted icon well (`.entity-icon-well`) placed directly before the wrapping resource name without a redundant type eyebrow, and actions where needed. Header actions stay beside the title at every width: the title column wraps its text, and actions shorten to icons below the `labels` threshold. View and collection-scope controls belong in the navigation or collection toolbar below the header rather than in the header action slot. Project and instrument detail headers show their human-facing identifier as secondary metadata only when it differs from the displayed title, and sample type or dataset measurement stays in Summary rather than repeating beneath the title. Page, card, and dialog descriptions appear only when they add context needed to understand scope, consequences, or constraints. Breadcrumbs stay on one line within the content width, with the sizing owned by the `Breadcrumb` primitive: the section root keeps its short label, ancestors such as a project shrink three times faster than the current page and stop at `--spacing-breadcrumb-ancestor`, and the current page shrinks last; every truncated segment ends in an ellipsis, shows its full name in a `TruncationTooltip` on hover or keyboard focus (closed while the text fits), and keeps its complete accessible name.

Route-backed resource section navigation uses 2.5 rem targets and the 0.875 rem semibold label role. Compact layouts reduce only horizontal tab padding and retain bounded horizontal scrolling when needed. Inactive tabs show a rounded neutral surface on hover, while the active tab adds a square-ended orange underline. Contextual creation actions and the entity `RefreshButton` align at the right edge of the tab row when space permits. Canonical sample and dataset Overview places `ResourceSiblingNavigationControls` beside section navigation: one ghost `Browse nearby` action when no sequence is active, or a compact button group (`size="icon"` outlined Previous and Next buttons flanking a truncated context and ordering button that opens the sequence configuration dialog) when active.

| Role        | Content                                                          | Layout behavior                                                                          |
| ----------- | ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| Action      | A short explanation and one launcher or consequential action     | Capped track that shares an adaptive row with peer actions and stacks on compact layouts |
| Reading     | Forms, access lists, members, operators, and prose               | Full width up to the semantic reading boundary                                           |
| Wide detail | Summary, identity, files, relationships, and structured metadata | Four-column or three-column span within the shared seven-column detail grid              |
| Workspace   | Tables, search results, files, and graphs                        | Full available content width with local containment where needed                         |
| State       | Missing, unavailable, and recovery content                       | Existing centered state boundary                                                         |

Card and section width follows content responsibility rather than available page space. Detail grids and action clusters use normal DOM order and CSS Grid auto-placement without CSS `order`, explicit row placement for optional content, duplicated markup, or masonry behavior; capability-gated and type-specific omissions collapse naturally. On wide screens, sample and dataset Overview uses the aside detail grid: Summary, Files, and Scientific metadata form the wide leading column, while Identity, Thumbnails, and Relationships form one trailing aside stack that spans both rows; compact screens stack Summary, Identity, Thumbnails, Files, Relationships, and Scientific metadata in one full-width column. Dataset thumbnails use an uncropped contained image on the card surface, a visible caption, lazy loading, and a `ManagementToggle` edit state with add, rename, and confirmed delete controls. Resource management cards compose `ManagementAction` entries in card presentation when standalone and row presentation when grouped.

Lists use flat full-width rows (`ResourceList`, `ResourceListItem`, `ResourceListItemContent`) or semantic tables, reserving cards for contained groups, summaries, empty states, and bounded metrics. Home's Recently added and Recently viewed cards and ownership cards share one compact resource-row structure (resource icon and linked name, icon-labelled project ID and monospaced supporting MFID below, and a browser-local Created or Viewed timestamp opposite). Relationship rows keep the wrapping identity and canonical action (`ResourceFullPageLink` in read mode, `UnlinkRelationshipAction` in management mode) on one row at every width without a redundant resource-type subtitle, and the Relationships card groups `ResourceGraphLink`, the primary Add action, and `ManagementToggle` in its footer. Scientific metadata uses the searchable full-width tree renderer: top-level fields remain visible, nested objects and structured arrays use 36 px native disclosure rows (the shared `Disclosure`, also used by the inspector's metadata section and the status diagnostics) with explicit counts (closed initially in nested levels and the inspector), short scalar arrays use compact JSON notation, long arrays reveal bounded increments, compact labels use the 12 px semibold role, scalar values remain 14 px monospaced text, and one compact expand-all or collapse-all control sits beside `EditableCardTrigger` in the card header.

## Tables and collections

Semantic table markup is the default; simple URL-backed and API-sorted tables do not add a headless table package. Declare column alignment through the `kind` prop on `TableHead`, `TableCell`, and `SortableTableHead`, which `src/components/ui/table.tsx` maps in one place:

| Kind      | Content                                                         | Alignment               |
| --------- | --------------------------------------------------------------- | ----------------------- |
| `text`    | Names, identifiers, storage backends, ingestors, people, status | Start (default)         |
| `numeric` | Sizes, counts, and other quantities                             | End, tabular numerals   |
| `date`    | Dates and times                                                 | Start, tabular numerals |
| `action`  | Trailing row actions                                            | End                     |
| `select`  | Row selection checkboxes                                        | Center                  |

Do not center text, status, or date columns; center only the fixed-width selection control, and use the same column kinds and groups in loading skeletons. Sortable column headers use `SortableHeaderButton` / `SortableTableHead`, expose `aria-sort`, name the next direction, and share label typography with static headers. Resource and person names are the only navigation target within an identity, using the selection-aware text link so pointer text selection does not trigger navigation while preserving native href, modifier-click, and keyboard behavior; supporting MFIDs, project IDs, usernames, subtypes, measurements, roles, and timestamps remain selectable plain text. The name of a stored file is a selectable text link that opens in a new tab and states so in its accessible name, while catalog-only file names stay plain text and file rows reserve a stable action slot for download status.

Resource collection, directory, and deletion-request tables share fixed semantic column widths for browser-local timestamps (`10.5rem` Created and Updated columns immediately before the trailing `ResourceFullPageLink` action, with Created hidden at intermediate widths and restored on wide screens) and abbreviated person columns, while identity, type, location, and project columns flex. Global sample and dataset tables show project identity as linked text with `IdentityHoverCard` in the Project column without repeating a project icon in every row; project-scoped tables replace the redundant Project column with Sample type or Measurement on wide screens. Compact layouts reflow table rows into labelled stacked records (with the field label and value starting on the same row and wrapped lines aligned beneath the value), use an equivalent item list, or use bounded table scroll, never page-wide horizontal scroll. In deletion-request review tables, selecting rows replaces the column headings in place with contextual bulk actions within the same row height.

Collection navigation, resource-type switching, `Group by` facet selection, ownership scope, and filter controls share one responsive toolbar that stays below the persistent app header on non-compact screens and stays in document flow on compact screens. Every directory uses `CollectionToolbar` in one order: the view or type switch, or a search field where the API supports text search, comes first; a single simple filter sits inline and two or more move to the Filters sheet; Refresh comes last. Table headers sort the list, and a `TableSortControl` Sort by select takes their place when rows stack; Filters sheets hold filters only. `CollectionFilterPanel` is a sheet as wide as the inspector with one column of titled `FilterSection`s (`FilterForm`): value lists use the searchable `FilterValuePicker` (most frequent first, the unspecified value pinned, more values loading inside the popup), two to four fixed options use the segmented `FilterChoice`, and date bounds use `DateRangeFilter`: typed dates for exact days above a range slider (the shadcn `Slider` on Base UI, 16 px handles with grab cursors) across the span the filtered records cover. Slider stops follow the calendar: days for up to three months of records, Monday-to-Sunday weeks for up to two years, months for up to 15 years, and years beyond; the start handle snaps to a period's first day, the end handle to its last, and a handle at either end leaves that bound open. Days count in the viewer's time zone. The sheet edits a draft: Reset restores the draft's defaults without changing the page, and Apply reads Show N with the draft's result count. A date range shows as one pill, `+N more` opens the sheet, Clear all beside the pills removes the applied filters but keeps the order, and an invalid link keeps every control with its error beside the field. Group directories use a full-bleed header and icon well (resource-tinted for projects, instruments, and owners, and neutral `muted` surface tints for other facets) and sortable header buttons for the displayed dimension (`SummaryFieldIcon` + label) and Count, reserving a tokenized count column while truncating long labels. The toolbar exposes up to three committed filters as `RemovablePill` outline controls (with subtle resource-tinted borders and surfaces for active project, instrument, and owner filters, and a neutral `muted` surface tint for other filters), summarizes additional filters with a count, and offers a Clear all action when multiple filters are active. Users and service-account directory search fields share the 250 ms debounce, three-character minimum, immediate Enter commit, below-minimum reset, and focus-restoring clear button with the application-bar quick search.

## Forms and overlays

Every form control has an accessible label, semantic grouping, validation announcement, and distinct required, optional (muted `(optional)` beside the label), disabled, read-only, pending, and failed states. Drafts survive failure until success or explicit discard. Identifier inputs with a live availability check (username, email, project ID, and instrument ID) use the shared fields in `src/features/forms/identifier-fields.tsx` with `useSlugConflict` to block submission on conflicts. Bounded chooser and autocomplete pickers debounce searches and display results in an anchored overlay (at least field width, with a wider floor on wide screens and a visible native scrollbar) so results never reflow the form. Facet-backed sample (`sample_type`) and dataset (`measurement`, `session_name`, and `data_format`) fields on creation and summary-editing forms use `FacetCombobox`, lazily loading existing facet values with counts (scoped to the resource's project when present, or workspace-wide otherwise), filtering options as the person types, offering an inline `Create "<value>"` item for novel values, and committing the typed value on selection, `Enter`, or `Tab`/blur. Sample and dataset creation forms use the shared split grid: primary and type-specific details stay visible in bordered sections in the leading card, while `Relationships`, `Scientific metadata` (key-value fields, JSON view, and JSON file upload), and dataset `Files` occupy separate cards in the trailing column. Metadata edit mode on existing resources uses a bounded vertically resizable monospace root-JSON workspace, requiring full-replacement confirmation when removing a top-level field.

Dialogs handle focused input (overlays are not stacked where avoidable: the mobile navigation drawer closes before it opens a dialog such as Shortcuts; a dialog that must open over a modal sheet, such as the compact or medium inspector, keeps a transparent backdrop so a press outside still closes it, and the sheet dims through Base UI's `data-nested-dialog-open` so the page and the sheet read as one dimmed layer), alert dialogs handle destructive confirmation, sheets handle contextual details or filters (such as the viewport-bounded collection filter sheet with its scrollable body and persistent Clear and Apply footer), and popovers handle small anchored content (such as the application-bar quick search combobox and QR scanner trigger). Dialog and alert-dialog surfaces stay within the dynamic viewport, own contained vertical scrolling, and keep their compact action footer aligned and visible. Reversible confirmations (such as publish and unpublish) use `ConfirmationDialog` with `kind="dialog"`, while consequential or destructive confirmations use `ConfirmationDialog` with `kind="alert"`; feature code does not compose dialog or alert-dialog primitives directly for confirmations. Multi-item operations may expose a pending Stop action only when it finishes the in-flight unit and prevents subsequent units cleanly.

#### Responsive layout

Window classes set the shell; content thresholds set everything inside it. Both live as tokens in `src/styles.css` (`--breakpoint-*` and `--container-*`), `src/lib/window-class.ts` mirrors the window classes for scripts (a unit test keeps them equal), and the design-token check rejects window breakpoints that change content layout outside the shell and generic container sizes on the content container.

| Window class | Window width                      | Navigation                                                                    | Inspector           | Top bar and margin                                                         |
| ------------ | --------------------------------- | ----------------------------------------------------------------------------- | ------------------- | -------------------------------------------------------------------------- |
| compact      | below `--breakpoint-md` (48 rem)  | drawer                                                                        | modal sheet         | icon-only Create, account avatar only, no shortcut hint; 16 px side margin |
| medium       | from `md` (48 rem)                | icon rail; expanding it lasts until the window class changes and is not saved | modal sheet         | full top bar; 24 px side margin                                            |
| expanded     | from `lg` (64 rem)                | the saved sidebar choice                                                      | non-modal overlay   | full top bar; 32 px side margin                                            |
| wide         | from `--breakpoint-wide` (90 rem) | the saved sidebar choice                                                      | docked preview pane | full top bar; 32 px side margin                                            |

Every top bar control changes form at the same boundary. The side margin is one variable, `--page-margin`, set per window class in `src/styles.css` (the Material 3 window margins) and used through the `page-margin` spacing utility by the top bar, the page, the footer, and Back to top, so they always line up; the design-token check rejects the raw step tokens elsewhere. Vertical page spacing does not step: it stays at `--spacing-page-block` (24 px), so page titles never move vertically when the window changes size.

The browser reports its window class in the `crucible_hub_window` cookie so the server renders the right navigation mode.

Inside the shell, `main` is the named `content` container and cards, sheets, dialogs, field groups, and tables are containers too. Components query the nearest surface with unnamed variants (`@fields:`) or the page with the `content` name (`@split/content:`). Queries measure the content box, inside page gutters and card padding.

| Threshold         | Width  | Used for                                                            |
| ----------------- | ------ | ------------------------------------------------------------------- |
| `fields`          | 22 rem | Two fields, a label beside its value, or a row's parts side by side |
| `identifier-icon` | 26 rem | The MFID field icon                                                 |
| `table-columns`   | 30 rem | Optional table columns, such as file storage and size               |
| `fields-wide`     | 34 rem | Three fields side by side                                           |
| `labels`          | 42 rem | Page action labels; below it, actions show icons                    |
| `split`           | 48 rem | Page grids split into columns                                       |
| `directory-split` | 56 rem | The group directory beside its table                                |
| `table-detail`    | 56 rem | Processing table detail columns                                     |

Collection tables keep their own column-priority container rules next to the table styles.

## Resource inspector

The inspector is the route-addressable exception under [decision 0008](../decisions/0008-inspect-linked-resources-in-place.md) and uses one adaptive shadcn Sheet under [decision 0037](../decisions/0037-adapt-resource-inspector-to-viewport.md) with shared width, layer, surface, spacing, and motion roles. At widths where the underlying page remains visible, it is a non-modal complementary surface without a backdrop so the host collection or graph remains interactive; a non-interactive outside press or Escape dismisses it, scrolling the page by wheel or touch drag and focus movement alone keep it open, its scrolling stays inside it rather than moving the page behind, and activating an underlying link, control, or graph node completes without a competing close transition. At compact widths where it covers the page, it retains modal focus and backdrop behavior. On wide screens it is a persistent pane beside the content on every page: it keeps the last previewed resource while navigating, never moves the layout, does not slide, shows a short hint while empty, and can be hidden from the application header: the pane and its preview slide out and back in step with the content, and showing it again restores the same preview. Previews opened while it is hidden float over the page as on medium screens.

The inspector sheet has no colored accent bar; the resource icon well and title carry identity. A dedicated top bar keeps the ghost `Back` action on the left (stepping back through in-panel preview history when available, or closing the inspector otherwise) and `Close` on the right. Content begins below the bar with the resource icon in a resource-tinted icon well beside the wrapping resource name in the `title-section` role (clamped to two lines for long project titles with full accessible name), a dedicated left-aligned icon-labeled MFID row, any API-reported deletion-request status, and a centered full-width canonical Open action (`ResourceFullPageLink`). Known row identity supplies the pending icon and title; otherwise the title uses a shape-matched skeleton without flashing generic text. Below the header, border-divided sections (`border-t pt-4` with `title-section` headings) present icon-paired `Context` fields (using abbreviated owner and lead names, `ResourceIdentityLink` hover previews that navigate within the inspector on click, sample descriptions, visibility badges, record timestamps, paired creation and update timestamps on the same row, and `-` for unrecorded values), dataset `Thumbnails` (up to two side by side with arrow pagination), naturally sorted dataset `Files` (bounded to 10 items with `ListExpansionToggle`), `Relationships` (omitting relationship editing controls), and a collapsible `Scientific metadata` disclosure. Sample and dataset footers provide short `Open` (`ResourceFullPageLink`) and `Graph` (`ResourceGraphLink`) actions, plus `Delete` when `can_request_deletion` allows a request or one is pending; other resource types retain `Open`. Opening focuses the inspector heading, following an in-panel relationship resets only panel scroll and focuses the new heading, and closing restores the trigger or a stable page heading without altering host scroll.

### Resource graphs

Resource graphs use React Flow with ELK Layered inside a route-owned, bounded graph surface (`--graph-surface` recessed canvas behind `--graph-card` node cards), resolving all dimensions, colors, line styles, zoom limits, motion, direction, and layout spacing from semantic CSS tokens ([resource graph API handoff](resource-graph-api-handoff.md)). Node surfaces and their `1px` `--border-strong` boundary remain neutral; the resource icon badge carries type identity, and hover or highlight tints the boundary with the resource role. The current resource stays centered on initial layout with the selection-colored boundary and a `Current` eyebrow label, and lineage flows top-to-bottom by default at every width (with Horizontal orientation available in Graph options). Solid lineage edges (`2.25px` default, `3.25px` highlighted) use rounded step paths and open arrowheads (`12px`) whose normal, highlighted, and dimmed states stay synchronized; sample-dataset associations use dashed undirected edges routed between facing perimeter handles. Each node uses an inline horizontal card layout with a rounded resource-type icon badge on the left, left-aligned text in the center (two-line wrapping name and one-line supporting subtype or measurement), and an optional dataset thumbnail on the right. Hover or node focus emphasizes the selected node and its immediate neighborhood.

On touch devices, a single-finger drag outside fullscreen scrolls the page and shows a transient two-finger instruction, two fingers pan and pinch-zoom, and double-tap-and-hold zooms smoothly; on touch and compact viewports, tapping an unselected node highlights its neighborhood and reveals its directional expansion actions without opening the inspector, while a second tap on the selected node opens the inspector and tapping the background pane clears the selection. Zoom out, zoom in, fit, and center current resource share one viewport-control group, while Graph options (center, reset layout, canvas-only association visibility, dataset thumbnails enabled by default, and Vertical/Horizontal orientation) and native fullscreen remain separate; tooltips and menus portal into the graph surface during fullscreen. Expandable nodes attach circular outline `icon-circle` expansion buttons to the relevant node edge (above/below/right in vertical layout; left/right/below in horizontal layout), and keyboard-focusable graph nodes together with the Overview Relationships card and overlay inspector provide accessible inspection, directional expansion, and canonical navigation without a duplicate table below the canvas.

## Feedback and recovery

Feedback preserves page context: shared entity-shell, card-body, collection-table, and compact-resource-list pending states (`CollectionRowsPending`, `PanelState`, `PanelUpdateError`) keep breadcrumbs, navigation, controls, field labels, table headings, and card headings visible while replacing only unresolved values and rows with shape-matched skeletons. Loading, empty, unavailable, error, refreshing, stale, partial failure, disabled, selected, permission-limited, and destructive states are distinct and announced in text. Cursor-paginated collections show loaded and total counts when available, auto-load within a bounded viewport margin with an explicit outlined `Load more` fallback, stop auto-loading on error while preserving loaded rows and offering retry, and expose a floating `Back to top` button once the page heading leaves the viewport. Placeholder data never bridges across incompatible ownership, filter, scope, type, status, or search contexts.

Errors stay in their affected panel, row, file, dialog, or field where possible, formatted through the shared safe error formatter so correlation references remain available and unknown failures receive action-specific recovery copy. Route error boundaries preserve the nearest stable shell, show the API correlation ID or browser diagnostic reference, retry application errors through router invalidation, and reload the document on Vite preload errors. Polite top-right toasts, which move beside an open inspector or docked pane, acknowledge short completed mutations when the changed content is already visible or the editor closes; validation, errors, warnings, progress, destructive outcomes, partial completion, one-time credentials, propagation delays, and copy feedback remain inline and never rely on toasts. Toasts can be swiped up or sideways to dismiss them, as well as closed with their Close button or left to time out.

## Accessibility, responsiveness, and validation

Target WCAG 2.2 AA. Every workflow is keyboard operable with logical focus and no trap; focus is visible and unobscured. Keyboard shortcuts are listed in the Shortcuts dialog and never activate while typing in an editable field or interacting with a dialog. Normal text meets 4.5:1 contrast, and large text and meaningful boundaries or focus indicators meet 3:1. Support 200 percent zoom, text-spacing overrides, and reflow at 320 CSS px without two-dimensional page scrolling except bounded alternatives for tables and intrinsic scientific views. Meet target-size requirements, announce async status without stealing focus, provide correct landmarks, headings, labels, errors, table headers, and dialog semantics, and never require color, hover, drag, precise pointing, or animation. Graphs and scientific views require a textual or tabular essential-information alternative.

Desktop and laptop are primary: keep prose and form width bounded while allowing data and metadata workspaces to expand, preserve routes and MFIDs across breakpoints, retain primary action and entity identity without page overflow, make column loss explicit and reversible, and never let sticky UI obscure focus or content.

Foundation validation uses the token and component fixture surface ([`design-fixtures.md`](design-fixtures.md)), automated rejection of raw colors, inline styles, arbitrary values, primitive typography, raw buttons, and uncatalogued icons (`npm run design:check`), token-level contrast assertions, component semantic and keyboard coverage, screenshot-free responsive checks, automated accessibility checks, and manual critical-workflow review across loading, empty, error, stale, partial-failure, long, and dense states. Targeted screenshots are local review artifacts and are not committed or generated by CI. Exceptions must promote a named missing semantic role; permanent unexplained suppressions are not accepted.
