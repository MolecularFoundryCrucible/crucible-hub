# Safety measures review: October 14, 2026

Status: Point-in-time audit of local workstation, agent sandbox, static build/contract, runtime, and deployment safety controls in `crucible-hub` at commit `ad36576`.

Scope: Local environment isolation, file permissions, ignore rules, scenario launcher hygiene, agent sandbox mounts, static verification gates, authentication and session hardening, privilege boundaries, error redaction, and container/CI controls.

## 1. Local workstation, credentials, and agent sandbox isolation

- **Restricted secret file permissions (`0600`)**: Local secret overrides (`.env.api-staging.local`, `.env.hub-auth.local`, `.env.orcid-staging.local`) have `0600` (`-rw-------`) permissions restricted to the local user account.
- **Layered ignore boundaries**: [`.gitignore`](../../.gitignore), [`.dockerignore`](../../.dockerignore), and [`.gcloudignore`](../../.gcloudignore) all exclude `.env*` and `*.local`. The Docker and Cloud Build ignore files additionally exclude `*.pem`, `*.key`, `.secret`, and `config/env` so local scenario configs and key material cannot enter container build contexts.
- **Sanitized scenario launcher**: [`scripts/dev-scenario.mjs`](../../scripts/dev-scenario.mjs) strips 19 sensitive and mode-selecting environment variables (`CRUCIBLE_API_KEY`, `HUB_AUTH_CLIENT_SECRET`, `HUB_SESSION_KEYS`, `HUB_SESSION_DATABASE_*`, `HUB_SESSION_REDIS_URL`, `HUB_PLATFORM_ADMIN_*`, `HUB_DATA_SOURCE`, `HUB_ENABLE_FIXTURES`) from the inherited shell environment before reading non-secret URLs from `config/env/<scenario>.env` and passing secrets only to the spawned dev server process.
- **Fail-closed default workspace mode**: [`src/data/crucible/workspace-config.server.ts`](../../src/data/crucible/workspace-config.server.ts) (`readWorkspaceConfiguration`) has no default `HUB_DATA_SOURCE`, so running bare `npm run dev` without an explicit scenario reports `unavailable` rather than connecting to a live API or silently enabling fixtures.
- **Loopback-bound dev server**: [`vite.config.ts`](../../vite.config.ts) binds the dev server to `127.0.0.1:3000` with `strictPort: true` and restricts `allowedHosts` to `["leviathan.rooster-chimaera.ts.net"]`.
- **Read-only agent command sandbox and masked host paths**: Inside the command execution sandbox (`/proc/self/mountinfo`), `/home/roncofaber/software/crucible-hub` and `/home/roncofaber/software/crucible-hub/.git` are mounted read-only (`ro`), `~/.config` and `~/.gitconfig` are mounted read-only, and sensitive host paths (`~/.ssh`, `~/.gemini/config`, `~/Desktop`, `~/Documents`, `~/Downloads`) are masked with read-only `tmpfs` deny mounts (`size=0k,mode=000`).
- **Git identity guard**: `~/.gitconfig` sets `user.useConfigOnly = true` and `push.default = simple`, preventing commits with guessed author identities or unintended multi-branch pushes.

## 2. Static, contract, and build-boundary gates

- **Server-only module boundary probe**: Server modules import `@tanstack/react-start/server-only`, and [`scripts/check-server-boundary.mjs`](../../scripts/check-server-boundary.mjs) runs a negative Vite build probe ([`tests/build/vite.import-protection.config.ts`](../../tests/build/vite.import-protection.config.ts) importing [`tests/build/import-server-only.client.ts`](../../tests/build/import-server-only.client.ts) -> [`src/server/crucible/client.server.ts`](../../src/server/crucible/client.server.ts)) that fails if client bundles can resolve server modules.
- **Cryptographic OpenAPI contract lock**: [`scripts/check-openapi.mjs`](../../scripts/check-openapi.mjs) verifies the SHA-256 digest of [`contracts/crucible-api.json`](../../contracts/crucible-api.json) against [`contracts/crucible-api.lock.json`](../../contracts/crucible-api.lock.json) and checks that [`src/generated/crucible-api.ts`](../../src/generated/crucible-api.ts) matches a fresh `openapi-typescript` generation with zero drift.
- **Pinned agent skills and dependency audits**: [`skills-lock.json`](../../skills-lock.json) pins the external `shadcn` skill by SHA-256 hash, `npm run skills:stale` checks TanStack skills against [`package-lock.json`](../../package-lock.json), and `npm run audit` checks production dependencies at `--audit-level=high`.
- **Repository agent guardrails**: [`AGENTS.md`](../../AGENTS.md) and [`CLAUDE.md`](../../CLAUDE.md) prohibit reading or logging credentials, exposing API keys to browser JavaScript or storage, calling live APIs or mutating live records without explicit authorization, hand-editing generated OpenAPI types, or starting conflicting `vite dev` servers.

## 3. Runtime, authentication, and deployment hardening

- **Security headers, correlation IDs, and CSRF enforcement**: [`src/start.ts`](../../src/start.ts) attaches `Content-Security-Policy` (`frame-ancestors 'none'; base-uri 'self'; object-src 'none'`), `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin`, a server-generated `X-Correlation-ID` (ignoring inbound correlation headers), `Cache-Control: private, no-store` on HTML responses in `hub-auth` mode, and CSRF `Origin` validation on all non-`GET`/`HEAD`/`OPTIONS` requests (reinforced in [`src/routes/auth.logout.ts`](../../src/routes/auth.logout.ts)).
- **Production fail-closed startup guards**: [`src/data/crucible/workspace-config.server.ts`](../../src/data/crucible/workspace-config.server.ts) rejects `HUB_DATA_SOURCE=api` when `NODE_ENV=production` so a shared server API key cannot be used in production, requires `https:` for `CRUCIBLE_API_BASE_URL` unless targeting a loopback host, and gates production `hub-auth` behind `productionHubAuthReady` (`HUB_AUTH_PRODUCTION_ENABLED=true` and a production-safe `HUB_AUTH_SESSION_MODE` in [`src/server/crucible/hub-auth.server.ts`](../../src/server/crucible/hub-auth.server.ts)). [`src/routes/fixture-uploads.ts`](../../src/routes/fixture-uploads.ts) returns `404` outside fixture development mode.
- **OAuth / OIDC hardening**: [`src/server/crucible/hub-auth.server.ts`](../../src/server/crucible/hub-auth.server.ts) enforces IP and pending-transaction rate limits (`enforceHubLoginRateLimit`: 20 attempts per IP per 60 seconds, 256 max pending transactions), S256 PKCE, constant-time `timingSafeEqual` state verification, open-redirect sanitization (`safeReturnTo` rejecting scheme-prefixed, protocol-relative, and `/auth/*` paths), `httpOnly` / `sameSite: "lax"` / `secure` cookies, and upstream token revocation on sign-out or failed callback completion.
- **Encrypted session storage at rest**: [`src/server/crucible/hub-session-store.server.ts`](../../src/server/crucible/hub-session-store.server.ts) hashes session and transaction keys with SHA-256 before storage (`hub_session:v1:sha256:...`) and encrypts payloads with AES-256-GCM (`hub-session:v1:<keyId>:<iv>:<tag>:<ciphertext>`) using a 32-byte key from `HUB_SESSION_KEYS` and binding the storage key as additional authenticated data (AAD), with multi-key rotation support.
- **Least-privilege Postgres session store**: [`migrations/session-store/0001_session_entries.sql`](../../migrations/session-store/0001_session_entries.sql), [`scripts/prepare-session-test-database.mjs`](../../scripts/prepare-session-test-database.mjs), and [`src/server/crucible/hub-session-postgres.server.ts`](../../src/server/crucible/hub-session-postgres.server.ts) separate DDL schema ownership (`crucible_hub_owner`) from runtime DML (`crucible_hub_app` limited to `SELECT, INSERT, UPDATE, DELETE`), revoke `CREATE` on schema `public`, enforce statement and query timeouts, and require Cloud SQL Connector in production unless explicitly overridden.
- **Explicit privilege-mode negotiation and verification**: [`src/server/crucible/client.server.ts`](../../src/server/crucible/client.server.ts) (`createCrucibleClient`) sends `Crucible-Privilege-Mode: standard` by default (`elevated` only when explicitly requested) and throws `CruciblePrivilegeModeError` (`502`) if the upstream response header does not match the requested mode. [`src/server/crucible/privilege-mode.server.ts`](../../src/server/crucible/privilege-mode.server.ts) (`requireAdministratorView`) blocks un-elevated administrative server functions with `403`.
- **Upstream error and credential redaction**: [`src/server/crucible/safe-call.server.ts`](../../src/server/crucible/safe-call.server.ts) and [`src/server/crucible/errors.server.ts`](../../src/server/crucible/errors.server.ts) strip upstream response bodies, stack traces, and credentials before returning structured errors with a `requestId` to the browser.
- **Container, proxy-header, and CI/CD hardening**: [`Dockerfile`](../../Dockerfile) builds in a separate stage and runs `.output` as the non-root `node` user; [`scripts/check-production-runtime.mjs`](../../scripts/check-production-runtime.mjs) verifies that untrusted `x-forwarded-host` and `x-forwarded-proto` headers are not reflected; [`cloudbuild.release.yaml`](../../cloudbuild.release.yaml) runs static validation, production smoke tests, and `npm audit` before resolving the image digest (`@${digest}`) for Cloud Run deployment; [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml) restricts `GITHUB_TOKEN` to `permissions: contents: read`.

## 4. Gaps and improvement opportunities

- **No active local Git hooks**: `.git/hooks/` contains only `.sample` files and `core.hooksPath` is unset, so `npm run secrets:check`, `npm run format:check`, and `npm run lint` do not run automatically on `git commit` or `git push`.
- **Narrow `scripts/check-secrets.mjs` patterns**: [`scripts/check-secrets.mjs`](../../scripts/check-secrets.mjs) checks only three token shapes (PEM private key headers, `AKIA...` AWS keys, and `gh[opsu]_...` GitHub tokens) and walks the filesystem while skipping `.env*` files. It will not flag an accidentally `git add -f`-tracked `.env.*.local` file (`git ls-files` check) or leaked `CRUCIBLE_API_KEY`, `HUB_AUTH_CLIENT_SECRET`, `HUB_SESSION_KEYS`, or `HUB_SESSION_DATABASE_PASSWORD` assignments in tracked files.
- **Vite temp directory under read-only sandbox mounts**: When the repository is mounted read-only in the command sandbox, `npm run boundary:check` and `npm run build` fail with `EROFS` because Vite writes temporary compiled config files under `node_modules/.vite-temp/`.
- **Shell sandbox mount vs. host file-edit tools**: While `run_command` mounts `/home/roncofaber/software/crucible-hub` read-only (`ro`), built-in host file tools (`write_to_file`, `replace_file_content`) execute outside the shell sandbox mount namespace and can write to the workspace unless restricted by tool-level permissions.
