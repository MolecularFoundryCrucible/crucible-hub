# Crucible Hub Design System

Status: Active design-system contract

Date: 2026-09-16

## Scope and principles

This document owns Hub tokens, themes, component policy, responsive behavior, accessibility, and visual validation. [`product-brief.md`](product-brief.md) owns product intent, [`information-architecture.md`](information-architecture.md) owns routes and navigation structure, [`architecture.md`](architecture.md) owns runtime boundaries, and [decision 0003](../decisions/0003-owned-design-system.md) owns the decision to use an owned system.

Hub is a desktop-first scientific workspace that shares Lens's semantic hierarchy and state discipline, not its phone dimensions, Compose structure, navigation, or Material defaults. Use semantic meaning before appearance, calm dense rows and tables, explicit accessible states, native HTML before managed primitives, usable full MFIDs, and one behavior contract across light and dark themes. Accessibility is a release property.

## Ownership and tokens

| Layer                                | Owner                        | Primitive values           |
| ------------------------------------ | ---------------------------- | -------------------------- |
| Primitive scales and semantic themes | `src/styles.css`             | Allowed only here          |
| Controlled shadcn primitives         | `src/components/ui`          | Shared tokens only         |
| Crucible domain components           | `src/components/crucible`    | Semantic tokens only       |
| Feature screens and routes           | `src/features`, `src/routes` | No primitive visual values |

Generated primitives enter `components/ui`, are reviewed, and become Hub-owned source. Feature code must not introduce colors, arbitrary utility values, shadows, type sizes, spacing, radii, breakpoints, z-index values, or motion durations. A missing role is a design-system change, not a local exception.

Primitive scales use a 4 px base and named spacing roles, repository-pinned self-hosted Noto Sans plus system monospace for MFIDs, shared radius and elevation roles, named layers, and named responsive breakpoints. Semantic utilities own each typography role completely: feature code does not recreate roles with primitive Tailwind size, weight, line-height, or tracking utilities. Shared class composition recognizes every semantic typography role as a font-size utility so foreground utilities cannot replace it. Use tabular numerals for changing data, selectable monospace MFIDs, and no interface text below 12 px.

| Role                                      | Size / line height / weight | Use                      |
| ----------------------------------------- | --------------------------- | ------------------------ |
| `title-page`                              | 28 / 36 px / 600            | Route title              |
| `title-entity`                            | 24 / 32 px / 600            | Entity title             |
| `title-section`                           | 18 / 28 px / 600            | Section, dialog, group   |
| `body-prominent`                          | 16 / 24 px / 400            | Spacious body and inputs |
| `body`, `identifier`, `label`             | 14 / 20 px / 400 or 600     | Rows, MFIDs, controls    |
| `supporting`, `label-compact`, `overline` | 12 / 16 px                  | Secondary content        |
| `metric`                                  | 24 / 32 px / 600            | Bounded summary          |

Top-level read-only field labels in Summary, Identity, Context, profile, and management cards use the 14 px semibold `label` role with muted foreground, and their values use the 14 px regular `body` or `identifier` role with normal foreground. Reserve the 12 px `supporting` role for hints, secondary identifiers, dense scientific metadata keys, and supplementary status text. Instructional copy, confirmations, and tooltips emphasize a referenced resource's displayed name with semantic strong text so it remains distinguishable from the surrounding wording, while accessible names remain plain-language actions.

Use 44 px minimum primary touch controls. Dense pointer-oriented rows may be 36 px only when each target is at least 24 by 24 px, separated, and keyboard reachable. Semantic layout roles include app header height, page gutter, content and reading widths, section gaps, dense pill roles, and a 320 px initially resizable metadata editor. Use restrained 4, 8, 12, and 16 px radius roles only after fixture calibration. Resting elevation is `level-0` flat, `level-1` sticky or raised, `level-2` menu or popover, and `level-3` modal. Cards use the card surface with a restrained boundary; popovers and dialogs use the raised popover surface with stronger elevation. Prefer surfaces and borders to decorative shadow. Shell breakpoints are compact below 48 rem, medium at 48 rem, wide at 64 rem, and expanded at 80 rem; components prefer container queries. Named layers cover base, sticky, navigation, popover, modal, notification, and emergency messages.

Use the quick, standard, and deliberate motion roles (`duration-fast`, `duration-standard`, `duration-deliberate`; 120, 180, and 240 ms) with the standard, enter, and exit easing roles (`ease-standard`, `ease-enter`, `ease-exit`). Bare `transition-*` utilities default to the quick role and standard easing, and the design-token check rejects numeric `duration-*` and Tailwind `ease-*` utilities. Overlays and hover feedback use the quick role; sheets, the sidebar, disclosure height, revealed list rows, and route-backed section changes use the standard role. Metadata disclosures animate their height through `::details-content`, rows revealed by Show all fade in, and resource, project, and instrument section tabs crossfade only the section panel through a router view transition while the header, tabs, and navigation stay still. Search-only navigation, such as filters and the inspector, never starts a view transition. Browsers without support change instantly. No continuous decoration. Reduced motion removes non-essential transforms, parallax, auto-scroll, continuous effects, disclosure height motion, and view-transition animation.

Themes use calibrated OKLCH values and foreground/background pairs for background, surface, card, popover, primary, secondary, muted, accent, destructive, success, warning, info, border, input, action border, ring, selection, sidebar, and data visualization. The light canvas uses a restrained cool neutral behind white cards and popovers, while muted, secondary, accent, and action surfaces remain distinct enough to communicate hierarchy without decorative color. Resource pairs cover sample, dataset, project, instrument, person, file, and service account. Combined Data navigation uses the Crucible dark-blue and light-blue brand pair, while individual datasets remain green, samples remain purple, files use a subdued slate-blue identity, and person identity uses cyan-teal, distinct from project blue and the contrast-adjusted instrument orange. Renderers derive categorical identity from the same resource roles used by normal application surfaces. State, type, permission, and lifecycle always also use text, icon, shape, position, or pattern. Do not derive hierarchy with arbitrary foreground opacity.

Light, dark, and system preferences share these roles. Resolve theme before first paint, set `color-scheme`, react to system changes only in system mode, and persist only the preference, never derived colors. Any browser preference must be account-neutral and safely cleared or recomputed on identity change. Validate every semantic pair in both modes.

Badges use semantic variants rather than feature-level color classes. Semantic status badges use a quiet tinted surface, semantic foreground, and restrained boundary so routine states do not compete with actions: success green for Valid, Complete, and Active; information blue for pending, queued, running, and processing; warning orange for maintenance, retrying, limited results, and states requiring attention; and destructive red for failed, invalid, and decommissioned states. Neutral metadata, roles, counts, visibility, and editing context use default, secondary, outline, or their dedicated domain variants because they do not express severity. Public and Private use the shared neutral visibility badge label paired with the semantic visibility field icon. Member role badges name the role, communicate hierarchy by order, and use a low-intensity semantic surface, role-colored foreground, and subtle border in both themes (with a neutral fallback for unknown roles); a project owner is presented as Lead in project membership surfaces while the underlying authorization role remains `owner`.

## Identity and credentials

Person identity uses the shared `PersonIdentity` primitive (`inline` for full or first-initial name in dense fields, `collection` for single-line truncated table rows, `stacked` for name over normalized `@username` with an accessible principal-type icon, and `avatar` to add a small, default, or large initial avatar). Human identities use the person icon and person-colored avatar border, while service accounts use the robot icon and semantic service-account violet for both the icon and avatar border around the same neutral fill. The API account-type field is authoritative, and visible icon shape plus its accessible name keeps the distinction independent of color. Shared identity, tooltip, and search presentations use the `@username` handle form for both people and service accounts, while page titles, explicitly labelled username or account fields, credential workflows, copied values, and accessible names use the raw username without `@`. Missing names fall back through supplied display name, raw username, and MFID; missing usernames use consistent unavailable copy.

Resource identity uses `ResourceIdentity` for the semantic type icon, display name, optional context, and optional MFID in stacked and collection presentations. Samples and datasets fall back to `Untitled sample` or `Untitled dataset` when a name is missing or blank; projects and instruments fall back to their project or instrument ID and then their canonical MFID. Resource names expose preferred break opportunities after scientific separators while preserving their visible and copied value. Sample and dataset search identities show the project icon and project ID followed by a middle-dot separator and sample type or measurement on the same supporting line when the search response provides them.

`PersonLink` provides canonical person navigation with the shared `IdentityHoverCard` preview wherever a person identity is linked. `ResourceIdentityLink` uses `IdentityHoverCard` only for project and instrument references inside sample and dataset lists or detail pages, where previewing context avoids interrupting the data workflow; project and instrument identities on their own directories, Home, search, access, and other primary navigation surfaces remain direct links without hover previews. Hover previews repeat the entity identity (with avatar on the left for people), place the fixed-length MFID on its own non-wrapping full-width line, and show only context already available to the current surface. They open on pointer hover or keyboard focus, suppress browser-native title tooltips, never contain information required to navigate or understand the row, and follow the canonical link directly on activation. Chooser buttons use display-only identity primitives so selection does not navigate.

`MfidText` owns identifier typography wherever copying is not offered, while `MfidValue` adds the standard copy action. Both use the 14 px `identifier` role for primary fields and a muted 12 px `supporting` presentation for secondary identity in rows, tooltips, choosers, search results, and the inspector. Resource identity includes a complete selectable MFID that uses the full card width, stays on one line when the compact viewport permits, and permits omission of its decorative field icon at the narrowest supported width so the identifier and copy action remain together. `MfidQrCode` renders the raw MFID at 112 px with a specification-compliant quiet zone, moves below the fields on narrow layouts without shrinking or forcing identifier wrapping, and opens a larger dialog view when activated.

Recognized timezone-aware ISO and PostgreSQL-style API timestamps display in browser-local time as abbreviated month, day, year, and 24-hour hour and minute (`Sep 6, 2026, 14:32`), using a deterministic UTC representation through the first client render and switching to browser-local formatting after hydration. Normalization accepts the API's space separator, microsecond precision, and compact UTC offsets without interpreting timezone-free values; native local date-time controls own editing and unrecognized values stay unchanged.

Human account and service-account views share the API credential card for non-secret validity, creation, expiry, loading, empty, and error states, placing Status, Created, and Expires on one row at wide widths and keeping creation and expiration together on compact and medium screens. Account capabilities use success-colored circle-check and destructive-colored circle-cross icons with accessible state names so availability remains understandable without color or status prose. Service-account administration reuses the shared person identity, service-account icon, role badge, table, card, form, dialog, and confirmation primitives, and its Identity card labels Username, Platform role, and Crucible ID while omitting the human-only email field. One-time credentials use a read-only monospaced field with an adjacent tooltip-wrapped copy action and explicit copy that the value cannot be shown again. Secret values never appear in collection rows, identifiers, notifications, links, or persistent UI state.

## Icons and actions

Routes, features, and Crucible domain components import Lucide icons only through the shared semantic catalog (`src/components/crucible/icons.ts`) or semantic icon wrappers; controlled UI primitives may own their internal implementation icons. The shared resource and principal type icon components own icon selection and semantic color while call sites supply only layout classes. Summary values and collection group facets share `SummaryFieldIcon` (colored semantic icons for linked projects and instruments, neutral icons for descriptive fields), and Identity values share a field-icon mapping for MFID, visibility, owner (selecting person or service-account icon from resolved owner type), and timestamps. Decorative icons are hidden from assistive technology (`aria-hidden="true"`), and icons inside buttons or button-styled links declare `data-icon="inline-start"` or `data-icon="inline-end"`. Icon-only controls require persistent resource-specific accessible names and visible tooltips, and are reserved for obvious low-risk actions; text remains for unfamiliar, destructive, ambiguous, or qualified actions. No emoji, logo, or brand mark is a normal UI icon.

Recurring domain action patterns own their canonical icons, button variants, sizes, and accessible labels so features and routes do not recombine them ad hoc:

- `EditableCardTrigger` and `EditableCardActions` own read-first card Edit triggers (`EditResourceIcon`), outline Cancel, primary Save, form association, disabled state, and pending feedback.
- `CreationFormActions` owns outline Cancel and content-width submit actions (`Create` or `Register` with `PendingIcon` and multi-stage retry labels).
- `ManagementToggle` owns the pressed-state outline `Manage` / `Done` toggle and tooltip for inline list management modes.
- `ResourceFullPageLink`, `CardViewAllLink`, `ResourceCreationLink`, and `ResourceGraphLink` own canonical navigation and creation links across cards, tables, and the inspector.
- `RotateCredentialAction`, `AccessGrantListActions`, and `UnlinkRelationshipAction` own destructive/management triggers for credential rotation, access/membership/operator list footers, and relationship unlinking.
- `RefreshButton` owns the outlined refresh control, `aria-busy` state, spinning icon, and last-updated tooltip across entity headers, the global Data toolbar, and the system status popover.

The shared `Button` primitive and `buttonVariants` helper are the only sources for general action typography, surfaces, borders, radii, internal spacing, heights, and icon sizing:

- `default` (filled primary pair): primary workflow commits and section-level primary actions (adding a member, operator, access grant, or relationship; publishing; choosing a project or new owner).
- `secondary` (filled neutral pair): selected filter controls or moderate emphasis.
- `outline` (neutral action surface with stronger semantic action border): cancel actions, retry and refresh controls, read-first edit triggers, navigation utilities, and toggle controls that switch to the secondary surface via `aria-pressed`.
- `ghost` (no resting container): low-emphasis actions, unselected filter pills, and dense table/header utilities.
- `warning` (warning foreground and quiet warning surface): active states requiring continued attention, such as the persistent Administrator view control.
- `destructive` (tinted destructive surface, destructive foreground, subtle destructive border) and `destructive-solid` (filled destructive surface for final confirmation footers): inline destructive entry points and irreversible confirmations, including credential rotation, revocation, leaving a project, and deletion.
- `graph` (graph surface, boundary, foreground, hover, and circular size): bounded graph node expansion controls.

Hover states may change the action surface but must retain its paired foreground. Confirmation footers do not repeat trigger icons; they show only action text and `PendingIcon` while pending. A Base UI `Button` that renders a navigation link sets `nativeButton={false}`. Feature-level `className` values may control external layout (width, flex, alignment, position) but must not override visual or sizing rules. Responsive collection links use the `table-action` size, floating Back to top controls use `floating`, MFID QR triggers use `qr`, and sidebar utilities use `SidebarMenuButton`. The design-token check enforces these boundaries and rejects raw buttons and visual `Button` overrides outside `src/components/ui`.

Small mutually exclusive view and scope choices use `SegmentedControl` (built on Toggle Group) with compact text labels on a muted group surface and the standard action surface and border for the selected option. The shared `Switch` primitive owns toggle dimensions, focus treatment, and semantic color variants (including `warning` for Administrator view). Direct interactive switch, sidebar, and menu-item controls use the pointer cursor while retaining native keyboard and focus behavior.

## Primitives and composition

[Decision 0006](../decisions/0006-use-base-ui-primitives.md) selects Base UI. Pin it in `components.json`, use the official shadcn CLI and registry, preview changes, and never overwrite Hub modifications without review. Install primitives only when needed and treat `src/components/ui` as the current inventory. Community registry components require provenance, dependency, license, source, accessibility, and theme review. Domain components accept semantic data and actions, never authorize or infer permissions, and presentational components do not fetch.

The application shell uses the square Crucible Hub logo as sidebar artwork and browser favicon, while the standalone Crucible Hub icon remains available for reviewed brand uses without a background. Crucible dark blue, light blue, and orange have dedicated brand roles: a softened light-blue surface identifies the light sidebar, dark blue identifies the dark sidebar, and the contrast-adjusted selection role based on Crucible orange marks the current destination boundary (`aria-current`) without replacing resource-type or state colors. Standalone sign-in and sign-in error pages share a centered card shell without the sidebar, using a restrained orange card accent, the Hub mark beside the sign-in title, a content-width outlined ORCID action, a faint background Explorer logo on sign-in, and a warning icon with one retry action on the error card.

The expanded desktop sidebar uses a 16 rem reading width, places the 1 rem brand label at top, uses the 0.875 rem body and label roles for destinations, scrolls its destination groups independently when height is constrained, and keeps Shortcuts, Theme (opening a System/Light/Dark radio menu), and Collapse navigation as standard labeled menu rows in its footer. The collapsed sidebar centers the logo on the same column axis as its navigation and footer icons, represents Recent with one history action and anchored menu, condenses the Administrator view switch to a pressed shield icon (`shield-minus` when off, `shield-plus` with warning surface when on), and presents footer utilities as vertically stacked icons with named tooltips. Only the compact drawer trigger remains in the application bar on narrow screens.

Page headers use one route title, an optional semantic identity icon placed directly before the wrapping resource name without a redundant type eyebrow, and actions where needed. A compact icon utility stays aligned with the title at every width, while textual or multi-control action groups may wrap below the title when width is constrained. View and collection-scope controls belong in the navigation or collection toolbar below the header rather than in the header action slot. Project and instrument detail headers show their human-facing identifier as secondary metadata only when it differs from the displayed title, and sample type or dataset measurement stays in Summary rather than repeating beneath the title. Page, card, and dialog descriptions appear only when they add context needed to understand scope, consequences, or constraints. Breadcrumbs stay on one line within the content width: structural ancestors and separators retain stable space, intermediate project labels use their natural width up to the bounded ancestor maximum, and the current entity truncates visually within the remaining width while preserving its complete accessible name.

Route-backed resource section navigation uses 2.5 rem targets and the 0.875 rem semibold label role. Compact layouts reduce only horizontal tab padding and retain bounded horizontal scrolling when needed. Inactive tabs show a rounded neutral surface on hover, while the active tab adds a square-ended orange underline. Contextual creation actions and the entity `RefreshButton` align at the right edge of the tab row when space permits. Canonical sample and dataset Overview places `ResourceSiblingNavigationControls` beside section navigation: one outlined `Browse nearby` action when no sequence is active, or a compact button group (`size="icon"` outlined Previous and Next buttons flanking a truncated context and ordering button that opens the sequence configuration dialog) when active.

| Role        | Content                                                          | Layout behavior                                                                          |
| ----------- | ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| Action      | A short explanation and one launcher or consequential action     | Capped track that shares an adaptive row with peer actions and stacks on compact layouts |
| Reading     | Forms, access lists, members, operators, and prose               | Full width up to the semantic reading boundary                                           |
| Wide detail | Summary, identity, files, relationships, and structured metadata | Four-column or three-column span within the shared seven-column detail grid              |
| Workspace   | Tables, search results, files, and graphs                        | Full available content width with local containment where needed                         |
| State       | Missing, unavailable, and recovery content                       | Existing centered state boundary                                                         |

Card and section width follows content responsibility rather than available page space. Detail grids and action clusters use normal DOM order and CSS Grid auto-placement without CSS `order`, explicit row placement for optional content, duplicated markup, or masonry behavior; capability-gated and type-specific omissions collapse naturally. On wide screens, sample and dataset Overview uses the aside detail grid: Summary, Files, and Scientific metadata form the wide leading column, while Identity, Thumbnails, and Relationships form one trailing aside stack that spans both rows; compact screens stack Summary, Identity, Thumbnails, Files, Relationships, and Scientific metadata in one full-width column. Authenticated account profile uses the same independent two-column principle so API credential follows Profile on the left while Account access occupies the right column. Overview lists that can grow without bound (such as Files and each relationship group) show their first 10 rows and expand in place through a Show all control rather than a nested scroll region. Dataset thumbnails use an uncropped contained image on the card surface, a visible caption, lazy loading, and a `ManagementToggle` edit state with add, rename, and confirmed delete controls. Resource management cards compose `ManagementAction` entries in card presentation when standalone and row presentation when grouped.

Lists use flat full-width rows (`ResourceList`, `ResourceListItem`, `ResourceListItemContent`) or semantic tables, reserving cards for contained groups, summaries, empty states, and bounded metrics. Home's Recently added and Recently viewed cards and ownership cards share one compact resource-row structure (resource icon and linked name, icon-labelled project ID and monospaced supporting MFID below, and a browser-local Created or Viewed timestamp opposite). Relationship rows keep the wrapping identity and canonical action (`ResourceFullPageLink` in read mode, `UnlinkRelationshipAction` in management mode) on one row at every width without a redundant resource-type subtitle, and the Relationships card groups `ResourceGraphLink`, the primary Add action, and `ManagementToggle` in its footer. Scientific metadata uses the searchable full-width tree renderer: top-level fields remain visible, nested objects and structured arrays use 36 px native disclosure rows with explicit counts (closed initially in nested levels and the inspector), short scalar arrays use compact JSON notation, long arrays reveal bounded increments, compact labels use the 12 px semibold role, scalar values remain 14 px monospaced text, and one compact expand-all or collapse-all control sits beside `EditableCardTrigger` in the card header.

## Tables and collections

Semantic table markup is the default; simple URL-backed and API-sorted tables do not add a headless table package. Declare column alignment through the `kind` prop on `TableHead`, `TableCell`, and `SortableTableHead`, which `src/components/ui/table.tsx` maps in one place:

| Kind      | Content                                                         | Alignment               |
| --------- | --------------------------------------------------------------- | ----------------------- |
| `text`    | Names, identifiers, storage backends, ingestors, people, status | Start (default)         |
| `numeric` | Sizes, counts, and other quantities                             | End, tabular numerals   |
| `date`    | Dates and times                                                 | Start, tabular numerals |
| `action`  | Trailing row actions                                            | End                     |
| `select`  | Row selection checkboxes                                        | Center                  |

Do not center text, status, or date columns; center only the fixed-width selection control, and use the same column kinds and groups in loading skeletons. Sortable column headers use `SortableHeaderButton` / `SortableTableHead`, expose `aria-sort`, name the next direction, and share label typography with static headers. Resource and person names are the only navigation target within an identity, using the selection-aware text link so pointer text selection does not trigger navigation while preserving native href, modifier-click, and keyboard behavior; supporting MFIDs, project IDs, usernames, subtypes, measurements, roles, and timestamps remain selectable plain text. The name of a stored file is a selectable text link that opens in a new tab and states so in its accessible name, while catalog-only file names stay plain text and file rows reserve a stable action slot for download status.

Resource collection, directory, and deletion-request tables share fixed semantic column widths for browser-local timestamps (`10.5rem` Created and Updated columns immediately before the trailing `ResourceFullPageLink` action, with Created hidden at intermediate widths and restored on wide screens) and abbreviated person columns, while identity, type, location, and project columns flex. Global sample and dataset tables show project identity as linked text with `IdentityHoverCard` in the Project column without repeating a project icon in every row; project-scoped tables replace the redundant Project column with Sample type or Measurement on wide screens. Compact layouts reflow table rows into labelled stacked records (with the field label and value starting on the same row and wrapped lines aligned beneath the value), use an equivalent item list, or use bounded table scroll, never page-wide horizontal scroll. In deletion-request review tables, selecting rows replaces the column headings in place with contextual bulk actions within the same row height.

Collection navigation, resource-type switching, `Group by` facet selection, ownership scope, and filter controls share one responsive toolbar that stays below the persistent app header on non-compact screens and stays in document flow on compact screens. Group directories use sortable header buttons for the displayed dimension (`SummaryFieldIcon` + label) and Count, reserving a tokenized count column while truncating long labels. The toolbar exposes up to three committed filters as `RemovablePill` outline controls, summarizes additional filters with a count, and offers a Clear all action when multiple filters are active. Users and service-account directory search fields share the 250 ms debounce, three-character minimum, immediate Enter commit, below-minimum reset, and focus-restoring clear button with the application-bar quick search.

## Forms and overlays

Every form control has an accessible label, semantic grouping, validation announcement, and distinct required, optional (muted `(optional)` beside the label), disabled, read-only, pending, and failed states. Drafts survive failure until success or explicit discard. Identifier inputs with a live availability check (username, email, project ID, and instrument ID) use the shared fields in `src/features/forms/identifier-fields.tsx` with `useSlugConflict` to block submission on conflicts. Bounded chooser and autocomplete pickers debounce searches and display results in an anchored overlay (at least field width, with a wider floor on wide screens and a visible native scrollbar) so results never reflow the form. Facet-backed sample (`sample_type`) and dataset (`measurement`, `session_name`, and `data_format`) fields on creation and summary-editing forms use `FacetCombobox`, lazily loading existing facet values with counts (scoped to the resource's project when present, or workspace-wide otherwise), filtering options as the person types, offering an inline `Create "<value>"` item for novel values, and committing the typed value on selection, `Enter`, or `Tab`/blur. Sample and dataset creation forms use the shared split grid: primary and type-specific details stay visible in bordered sections in the leading card, while `Relationships`, `Scientific metadata` (key-value fields, JSON view, and JSON file upload), and dataset `Files` occupy separate cards in the trailing column. Metadata edit mode on existing resources uses a bounded vertically resizable monospace root-JSON workspace, requiring full-replacement confirmation when removing a top-level field.

Dialogs handle focused input, alert dialogs handle destructive confirmation, sheets handle contextual details or filters (such as the viewport-bounded collection filter sheet with its scrollable body and persistent Clear and Apply footer), and popovers handle small anchored content (such as the application-bar quick search combobox and QR scanner trigger). Dialog and alert-dialog surfaces stay within the dynamic viewport, own contained vertical scrolling, and keep their compact action footer aligned and visible. Reversible confirmations (such as publish and unpublish) use `ConfirmationDialog` with `kind="dialog"`, while consequential or destructive confirmations use `ConfirmationDialog` with `kind="alert"`; feature code does not compose dialog or alert-dialog primitives directly for confirmations. Multi-item operations may expose a pending Stop action only when it finishes the in-flight unit and prevents subsequent units cleanly.

### Resource inspector

The inspector is the route-addressable exception under [decision 0008](../decisions/0008-inspect-linked-resources-in-place.md) and uses one adaptive shadcn Sheet under [decision 0009](../decisions/0009-overlay-resource-inspection.md) with shared width, layer, surface, spacing, and motion roles. At widths where the underlying page remains visible, it is a non-modal complementary surface without a backdrop so the host collection or graph remains interactive; a non-interactive outside press or Escape dismisses it, focus movement alone keeps it open, and activating an underlying link, control, or graph node completes without a competing close transition. At compact widths where it covers the page, it retains modal focus and backdrop behavior.

A dedicated top bar keeps the outlined `Previous preview` action on the left and `Close` on the right. Content begins below the bar with the resource icon beside the wrapping resource name in the `title-section` role (clamped to two lines for long project titles with full accessible name), a dedicated left-aligned icon-labeled MFID row, any API-reported deletion-request status, and a centered full-width canonical Open action (`ResourceFullPageLink`). Known row identity supplies the pending icon and title; otherwise the title uses a shape skeleton without flashing generic text. Sample and dataset footers provide short `Open` (`ResourceFullPageLink`), `Graph` (`ResourceGraphLink`), and `Delete` actions; other resource types retain `Open`. Opening focuses the inspector heading, following an in-panel relationship resets only panel scroll and focuses the new heading, and closing restores the trigger or a stable page heading without altering host scroll. Relationship editing controls are omitted from the inspector.

### Resource graphs

Resource graphs use React Flow with ELK Layered inside a route-owned, bounded graph surface, resolving all dimensions, colors, line styles, zoom limits, motion, direction, and layout spacing from semantic CSS tokens ([resource graph API handoff](resource-graph-api-handoff.md)). Node surfaces remain neutral while sample and dataset boundaries and icons use their canonical resource identity roles. The current resource stays centered on initial layout with the selection-colored boundary, and lineage flows top-to-bottom by default at every width (with Horizontal orientation available in Graph options). Solid lineage edges use rounded step paths and compact open arrowheads whose normal, highlighted, and dimmed states stay synchronized; sample-dataset associations use lighter dashed undirected edges. Each node centers an icon-and-copy group with left-aligned text (two-line wrapping name and one-line supporting subtype or measurement). Hover emphasizes the selected node and its immediate neighborhood.

On touch devices, a single-finger drag outside fullscreen scrolls the page and shows a transient two-finger instruction, two fingers pan and pinch-zoom, and double-tap-and-hold zooms smoothly. Zoom out, zoom in, and fit share one viewport-control group, while Graph options (center, reset layout, canvas-only association visibility, opt-in dataset thumbnails, and Vertical/Horizontal orientation) and native fullscreen remain separate; tooltips and menus portal into the graph surface during fullscreen. Expandable nodes attach circular `graph`-variant expansion buttons to the relevant node edge (above/below/right in vertical layout; left/right/below in horizontal layout), and the expanded native relationship card and table below the canvas provide equivalent keyboard-accessible inspection, directional expansion menus, and canonical navigation so the graph is never the sole representation of provenance.

## Feedback and recovery

Feedback preserves page context: shared entity-shell, card-body, collection-table, and compact-resource-list pending states (`CollectionRowsPending`, `PanelState`, `PanelUpdateError`) keep breadcrumbs, navigation, controls, field labels, table headings, and card headings visible while replacing only unresolved values and rows with shape-matched skeletons. Loading, empty, unavailable, error, refreshing, stale, partial failure, disabled, selected, permission-limited, and destructive states are distinct and announced in text. Cursor-paginated collections show loaded and total counts when available, auto-load within a bounded viewport margin with an explicit outlined `Load more` fallback, stop auto-loading on error while preserving loaded rows and offering retry, and expose a floating `Back to top` button once the page heading leaves the viewport. Placeholder data never bridges across incompatible ownership, filter, scope, type, status, or search contexts.

Errors stay in their affected panel, row, file, dialog, or field where possible, formatted through the shared safe error formatter so correlation references remain available and unknown failures receive action-specific recovery copy. Route error boundaries preserve the nearest stable shell, show the API correlation ID or browser diagnostic reference, retry application errors through router invalidation, and reload the document on Vite preload errors. Polite top-right toasts acknowledge short completed mutations when the changed content is already visible or the editor closes; validation, errors, warnings, progress, destructive outcomes, partial completion, one-time credentials, propagation delays, and copy feedback remain inline and never rely on toasts.

## Accessibility, responsiveness, and validation

Target WCAG 2.2 AA. Every workflow is keyboard operable with logical focus and no trap; focus is visible and unobscured. Keyboard shortcuts are listed in the Shortcuts dialog and never activate while typing in an editable field or interacting with a dialog. Normal text meets 4.5:1 contrast, and large text and meaningful boundaries or focus indicators meet 3:1. Support 200 percent zoom, text-spacing overrides, and reflow at 320 CSS px without two-dimensional page scrolling except bounded alternatives for tables and intrinsic scientific views. Meet target-size requirements, announce async status without stealing focus, provide correct landmarks, headings, labels, errors, table headers, and dialog semantics, and never require color, hover, drag, precise pointing, or animation. Graphs and scientific views require a textual or tabular essential-information alternative.

Desktop and laptop are primary: keep prose and form width bounded while allowing data and metadata workspaces to expand, preserve routes and MFIDs across breakpoints, retain primary action and entity identity without page overflow, make column loss explicit and reversible, and never let sticky UI obscure focus or content.

Foundation validation uses the token and component fixture surface ([`design-fixtures.md`](design-fixtures.md)), automated rejection of raw colors, inline styles, arbitrary values, primitive typography, raw buttons, and uncatalogued icons (`npm run design:check`), token-level contrast assertions, component semantic and keyboard coverage, screenshot-free responsive checks, automated accessibility checks, and manual critical-workflow review across loading, empty, error, stale, partial-failure, long, and dense states. Targeted screenshots are local review artifacts and are not committed or generated by CI. Exceptions must promote a named missing semantic role; permanent unexplained suppressions are not accepted.
