# Cloud Run pilot risk review

Status: Accepted for a restricted test-user pilot, pending deployed browser and proxy verification

The Hub serves `/hub/` through the existing `crucible.lbl.gov` Nginx proxy. Its Cloud Run service uses internal ingress, one configured instance, and a dedicated runtime identity. The API at `/api/v3` owns ORCID exchange, token issuance, revocation, authorization, and resource data. Hub keeps API access and refresh tokens in process memory and gives the browser an opaque `HttpOnly`, `Secure`, `SameSite=Lax` cookie. No Redis or Cloud SQL Hub session store is used in this pilot.

| Boundary                | Pilot control                                                                                                                                            | Residual risk and release check                                                                                                                                                                                  |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Browser to Hub          | HTTPS proxy, exact public callback, cookie-scoped session, same-origin and CSRF checks on mutations                                                      | Verify actual proxy headers, cookie attributes, direct server-function rejection, and cross-tab logout with two test accounts.                                                                                   |
| Proxy to Cloud Run      | Internal ingress, same-project VM, TLS upstream, preserved `/hub/` path                                                                                  | The same-project VPC can invoke the service without IAM. Verify VM access and deny direct internet access to `run.app`; do not broaden ingress to make routing work.                                             |
| Hub to API              | Server-only bearer transport, explicit normal privilege by default, API authorization on every operation                                                 | The existing API ingress and proxy-to-API transport limitations were explicitly deferred for the pilot. Keep users restricted, retain the existing API route, and revisit these controls before broader release. |
| Hub process memory      | One configured instance, affinity, bounded idle and absolute session expiry, coordinated refresh within the process                                      | Replacement, brief overscaling, or misrouting can sign users out. This is accepted for the pilot; no session continuity or traffic splitting is promised.                                                        |
| Hub runtime secret      | Dedicated service identity with access only to pinned Hub client-secret version 1                                                                        | Verify the binding and never grant the runtime identity ORCID credentials or an API key.                                                                                                                         |
| Login callback and logs | One-time code exchange, callback URL removed by redirect, Nginx access log omits query, `_Default` Cloud Logging sink excludes Hub callback request logs | Cloud Run generates request URLs before routing. Verify the exclusion and any inherited sinks, CDN logs, and application logs with a synthetic callback before a real sign-in.                                   |
| Image and contract      | Reviewed clean Hub commit, pinned API OpenAPI artifact, immutable image digest                                                                           | Build only from the reviewed commit and deploy by digest after confirming the API revision and generated client.                                                                                                 |

The pilot can activate after the API release, proxy route, callback registration, exact image digest, and deployed browser checks in [the deployment runbook](cloud-run-pilot.md) are confirmed. If sign-in, cookie handling, origin checks, API access, or callback logging fails, disable the Hub proxy route and production auth flag. Do not fall back to an API key or expose the service publicly. Before multi-instance scaling, implement the Hub-owned shared session store in [decision 0033](../decisions/0033-use-existing-cloud-sql-for-shared-hub-sessions.md).
