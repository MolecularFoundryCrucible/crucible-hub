## Current validation baseline

At commit `8b99faf`, `npm run validate:static` passes 418 unit tests across 56 files plus formatting, lint, strict types, OpenAPI drift, server-boundary protection, token policy, documentation links, and secret scanning. `npm run test:browser` passes 42 tests across six focused files in about 18 seconds, `npm run test:production` builds the application and passes six runtime checks, and `npm run audit` reports no high or critical advisories. The test tree contains no committed screenshots and is approximately 88 KB. CI runs two parallel jobs: static and unit validation, and browser plus production-runtime validation. `npm run validate` remains the complete local gate and adds the production build to `validate:static`. This register summarizes existing evidence and does not imply that every check was rerun for each documentation or UI-only iteration.

All evidence above is fixture or controlled-test evidence unless explicitly marked otherwise. It does not authorize live API access, deployment, release, or production mutation exposure.

## Authentication validation, 2026-09-28

An isolated Redis 7 container and synthetic credentials verified that a transaction can be consumed only once across processes, a cancelled transaction cannot create a session, a session created in one process can be read in another, exactly one of two competing compare-and-set updates succeeds, a rotated encryption key can read and rewrite an existing session, the old key can be retired after rewrite, and a session closed in one process is absent in another. With the temporary Redis service stopped, shared-session reads failed rather than falling back to process-local state. The container was removed after validation.

Local HTTP checks against the running development Hub verified a protected-page redirect to sign-in with `Cache-Control: private, no-store`, an S256 login redirect, `HttpOnly`, `Secure`, `SameSite=Lax` transaction-cookie attributes, invalid-callback recovery, rejection of a hostile logout origin, and acceptance of the configured origin. These requests did not authenticate a user or exercise refresh and revocation. The production runtime gate passed its six existing fixture-backed checks; it does not cover the authenticated deployment.

The production gate still needs a rotated local Hub client secret, a real ORCID sign-in on shared sessions, concurrent refresh across Hub replicas, logout and account replacement across tabs, secure cookies and cache clearing in the target browser, API revocation confirmation, and the deployment checks in [authentication transition](authentication-transition.md). No live user data or API mutation was used for this validation.
